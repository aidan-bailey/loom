# Loom wire protocol, version 1

Generated by `go test ./core/rpc -run TestProtocolReference -update`; do not edit.

Newline-delimited JSON frames (`core/rpc.Frame`). Each side's first frame is a hello
(`{"hello":{"protocol":1,"build":"…"}}`). A request is `{"id":N,"method":M,"params":{…}}`;
its reply `{"id":N,"result":{…},"error":{"code":…,"message":…}}` follows the events the
request produced. A cast has no id and no reply. An event is `{"event":Name,"data":{…}}`.
`{"fatal":{…}}` says the model panicked; every later call fails with it. A client is sent
the whole published state when it connects, then every change.

Kinds: **request** (a reply follows), **cast** (one way), **local** (a client answers it from its
replica of the published state; the server answers it as a request too).

## Barrier

`rpc.Ping` is a request that is no Core method: the server publishes what the model produced, then
replies `{}`, so every frame the server wrote before the reply has been read when it arrives.
`{"id":1,"method":"rpc.Ping","params":{}}`

## Refused hello

A server answers a hello of another protocol with an error frame that has no id, then closes:
`{"error":{"code":"mismatch","message":"rpc: protocol mismatch: this server speaks 1"}}`

## State events

The events that make up the published state, which a client's replica keeps, in the order the model
publishes them and a client's Sync hands them out, newest state only and ahead of the other events:

- WorkspacesChanged
- ModelChanged
- AccountsChanged
- GitHubChanged
- ViewsChanged (one per workspace, by its `WS`)

A server queues at most one of each (one per workspace for `ViewsChanged`) for a connection: a newer
one replaces an older one still queued, in its place. Replies and the other events keep their order.

## Errors

An error crosses as `{"code":C,"message":M}` (`core.WireError`). The code keeps the identity a receiver
tests with errors.Is, and every other error arrives as its message: `not_found`, `refused`, `storage`, `error`
(a failure that is none of the others), `panic` (the model panicked), `protocol` (a frame the other side could
not use; fatal to a client), `unsupported` (the peer does not know the method; an ordinary error, so a newer client
can probe an older server) and `mismatch` (a refused hello). Examples, a `Notice` and a `Reply` carrying one:

`{"event":"Notice","data":{"Err":{"code":"not_found","message":"no such session"}}}`

`{"event":"Reply","data":{"Req":2,"ID":3,"Err":{"code":"error","message":"kill x: worktree locked"},"Issue":{"Number":0,"Title":"","Body":"","URL":"","Labels":null,"Closed":false}}}`
