# Changing the web layer

`internal/web` is a `core.Core` client inside the daemon that serves a phone app (two: the classic one and the new React one, which a device picks), a JSON API, a server-sent stream and Web Push behind device pairing. Read this before adding a route, a stream event or a push kind, before changing the JSON the app reads, and before trying a change on a phone. The package's rules are in `internal/web/CLAUDE.md`; this is the procedure and the traps.

## Adding an API route

1. The Go types: a body and a response with `json` tags; a query type of `string` fields only, each tagged `query:"<name>"` (`readQuery` fills nothing else, `TestRoutes_QueryTypesHoldOnlyStrings`); each fixed-value string field a typed string listed in `unions()` with its values (`internal/web/unions.go`, `TestUnions_EveryFixedValueFieldIsTyped`).
2. The typed handler, `func (l *Layer) <name>(c *call, in In) (Out, error)`, beside its topic's file: `c.session()` for `{id}`; `c.act(send)` or `c.actCreated(send)` for a request that answers notices (a refusal is 409 with the model's text, a stopping daemon 503, a wait past `replyWait` 202 `{"pending": true}`; in the 202 and the 409 cases `settle` sends the notices raised so far to the device's stream, which keeps them, and returns them to the caller only when the request worked); `c.read(send)` for one whose `Reply` carries data (504 when `replyWait` runs out, the request dropped once answered); `&statusError{status, text}` for the handler's own refusals. Never copy the model's preconditions: `admit` decides, and the app's commands follow only the session's status. Check what the request carries as the Limits section of `internal/web/README.md` says.
3. The entry in `Layer.routes()` (`internal/web/routes.go`): `typed[In, Out](l, spec{method, path, log, client, ok, doc}, handler)`: `log` is the action its log line names, `client` a lowerCamelCase name unique in the table (the generated function's), `ok` the success status, and `doc` one to three sentences saying what the route does and refuses, limits included, which `docs/specs/web-api.md` prints beside it; `open` only for pairing; `page(...)` for an HTML page the client only builds the URL of.
4. `go generate ./internal/web`, then `CGO_ENABLED=0 go test ./internal/web/...`: the generator rewrites `internal/web/ui/src/api/gen.ts`, `docs/specs/web-api.md` and `internal/web/api.fields` (its new lines are appended; commit them), and `TestContract_GeneratedFilesAreFresh` fails until it has run. Add a case to the route tests and, for a lifecycle action, to `e2e/web_test.go`.
5. The app: call it as `api.<client>(…)` (`internal/web/ui/src/api/request.ts`) from a command (see Adding a command below) or a TanStack Query read, and give webshot's canned loom a fixture and an `apiRoutes` entry (`tools/webshot/canned.go`) so the route answers there. The classic app is frozen: it learns nothing of a new route.

## Adding a WebSocket route

The terminal route (`internal/web/terminal.go`, `internal/web/terminal_conn.go`) is the pattern: a route that upgrades, so its handler is hand-served and nothing of the typed adapter applies.

1. **The entry.** `page(l, spec{...}, handler)` with `ok: http.StatusSwitchingProtocols`, a `log` name and a `client` name; registration wraps it in `authed` as any closed route. Its `doc` must say it is a WebSocket upgrade: the generator prints every page entry as "HTML for the app's iframe", and the doc, printed above that line, is what tells a reader otherwise. The generated client builds only `<client>URL` (a path); the app makes the `ws:` or `wss:` URL from its own host.
2. **Refuse before the upgrade, as JSON.** The handler is a `deviceHandler`, behind `authed` and not behind an origin check: `guard` checks `Origin` only for a method but GET and HEAD, and an upgrade is a GET. Refuse a request that is not a WebSocket upgrade first of all, 426 (`isWebSocketUpgrade`: a GET at HTTP/1.1 or above with `Connection: upgrade` and `Upgrade: websocket`; the mux's `GET` pattern also serves HEAD), then one whose handshake the library would refuse, 400 (`validHandshake`: version 13 and exactly one `Sec-WebSocket-Key` that decodes to 16 bytes), so that neither takes a slot or asks the model for anything: `websocket.Accept` checks the handshake only after the slot is taken and the model has started a shell. Check `rule.allowsOrigin` on exactly one `Origin` header yourself, and call `websocket.Accept` with `InsecureSkipVerify: true` because the layer's rule is the stricter one. Answer every refusal with `l.refuse` before `Accept`: after it the connection is the library's and no status can be sent.
3. **Count before the work.** Reserve a slot under the part's lock before asking the model for anything (`terminals.reserve`), and release it in a `defer`: a connection counted only once its shell exists lets a burst past the caps while the model works, and a refusal that forgets the release leaks a slot until a restart. The reservation refuses while the part is closed or no listener runs, while the switch is off by the part's own copy (kept by its sink from `ModelChanged`), for a device the part has not read, and at the caps.
4. **End connections from the part, never from the listener.** `http.Server.Close` does not track a hijacked connection. The part is a sink (the switch off and a device revoked or paired again), `unbindLocked` calls its `endAll` after the rule is cleared and before the listener closes (a rebind), and `stopParts` calls its `close` (the layer's stop). A slot ended before its connection exists keeps the ending and hands it to the connection when it attaches.
5. **Run the connection with `context.Background()`, not the request's** (`websocket.Accept`'s documentation: the request's context is not safe to use afterwards), and pass the layer's `recoverPanic` into every goroutine the connection starts.
6. **Record the connection you hijack, and hand it to the connection.** Give `websocket.Accept` the writer `recordHijack(w)` returns and pass `hijacked()`, the connection Accept took, to `newTermConn`: the library's close handshake reads with no deadline whatever frame the browser is part-way through sending, and `http.Server.Close` does not track a hijacked connection, so only the connection closing that socket outright (`termCloseWait` after its close frame) frees a slot whose browser stalled.
7. **Log the open and the close** (device, session, reason) under the part's logger, never the bytes.
8. **Tests.** The connection runs over a real WebSocket pair on `httptest` against a fake attach (`startTermConn` in `internal/web/terminal_conn_test.go`); the route runs over `apiEnv` with the part's `ensure` and `newOpen` seams replaced (`scriptTerminals` in `internal/web/terminal_test.go`), so no test reaches tmux or the model's jobs. Pin each refusal and its both sides, and each ending as a close frame a client reads.
9. **The contract.** `go generate ./internal/web`, then `pnpm -C internal/web/ui run build`: the bundle holds `gen.ts`'s `api` object, so `pnpm run dist:check` fails until it is rebuilt.

## Adding a stream event

1. Publish it from a sink (`apply(evs []core.Event)`) through `l.hub.publish(event, data)` or `l.hub.sendTo(device, event, data)`. A sink never blocks and does no network I/O: the drain hands it every `Sync`'s events on one goroutine, and a stalled sink stalls every stream.
2. If a reconnecting phone needs the state, put it in the `snapshot` too: every connect starts with one and nothing is replayed.
3. Add the event's name and payload type to `streamEvents()` (`internal/web/stream.go`), then `go generate ./internal/web`; `gen.ts`'s `StreamEvents` gains the key, and the typecheck then fails in `KNOWN` (`internal/web/ui/src/api/stream.ts`) and in the store's `applied` (`internal/web/ui/src/store/fleet.ts`) until each handles it; the store's `afterEvent` switch (also `fleet.ts`) needs a label too, which the typecheck does not demand, so an event left out never schedules the snapshot's save. `TestContract_ReadsTheTablesAndUnions` (`internal/web/internal/gen/gen_test.go`) lists the event names by hand: add the new one in the table's order. The classic app ignores an event it has no handler for.
4. Document the event in the stream section of `internal/web/README.md`.

## Adding a push kind

1. Work the trigger out in `internal/web/triggers.go` from the projection's transitions, one push per transition. The first projection after the layer starts is a baseline and pushes nothing, and workspace terminals never push.
2. Add the kind to the payload (`kind`, `session`, `title`, `body`, `badge`, `url`), to the device's notification settings (`core.NotifySettings`, `PUT /api/v1/device`) and to the settings screen.
3. Choose `Urgency`, and keep the per-session `Topic` that `internal/web/triggers.go` makes (the session ID's 8 bytes as unpadded base64url), so an offline phone gets only the latest: Apple refuses a `Topic` whose length is 1 mod 4 with 400 `BadWebPushTopic`, and `webpush.NewRequest` refuses one too.
4. Show it in both workers, `internal/web/static/sw.js` and `internal/web/ui/public/sw.js`: the notification is tagged by session, because iOS requires every push to show something and loom cannot clear a stale one.

## Changing the JSON the app reads

The API is `/api/v1` and an installed app may be older than the daemon for a while. Add fields; never rename, retype or drop one: `internal/web/api.fields` pins every shipped field, route, event and union value and `TestContract_FieldsOnlyGrow` fails on a change, so a removal is a hand-deleted line in the same commit. The service worker updates the phone when the build ID differs from the snapshot's `build`, so a daemon upgrade upgrades the phone, but only after it has loaded the old shell once.

## Adding a panel

The panel's module is `internal/web/ui/src/panels/<id>/index.tsx` calling `definePanel({ id, title, appliesTo, tab, Head, Strip, Body })`; a new id is added to `PanelId` (`internal/web/ui/src/app/panels.ts`) and given its URL in `routeOf` and `hrefFor` (`internal/web/ui/src/app/routes.tsx`, with a case in `routes.test.ts` for the classic URL it replaces); `internal/web/ui/src/panels/index.ts` imports the module for its registration; a session's view takes its frame from the panel: `tab: { order, label, Mark }` puts a tab in the session's tabs, shown for the sessions and hosts `appliesTo(session, host)` accepts (`HostFacts` in `internal/web/ui/src/app/panels.ts`, read by `useHostFacts()` from the snapshot, so a tab can come and go on a stream event, as the terminal's does with the host's switch; a caller of `sessionTabs` or `appliesTo` passes it), where `Mark` (a component handed the session) is drawn after the label, `Head` is the context row (`SessionHead`), and `Strip` is a line under the tabs (the fact strip, the subagent's), each of the three in an error boundary of its own, so one that throws leaves the header and the other tabs; a `Body` draws `NoSession` when the snapshot lists no such session, and the conversation, info and mockup views call `useMarkSeen` (`internal/web/ui/src/fleet/seen.ts`) so the fleet's NEW mark clears; a read follows "Adding a read" below; a screen the first view does not need is a lazy `Body` (`Body: lazy(() => import("./JobBody"))`, a default export in a module of its own, as `internal/web/ui/src/panels/job/index.tsx` does) with its `Head` left in the entry: `PanelHost` draws it under a `Suspense` with a `Skeleton`, a chunk that fails to load reaches the panel's error boundary, which offers a reload, and a Go test like `TestDist_LazyViewsAreChunksOfTheirOwn` (`internal/web/static_budget_test.go`) pins that the chunk exists and that `internal/web/dist/index.html` names it nowhere (the chunk is pinned only once its module's stem (`FlowBody`, `NewSessionBody`, ...) is in the list `checkLazyViews` ranges over, so add the stem there and a case for it to the table of `TestCheckLazyViews_RefusesAMissingChunkAndAPreloadedOne`, in the same commit as the panel; and a view the first load needs stays in the entry: the conversation, info, changes and subagent views, which a push opens, and pairing, which an unpaired launch opens); a Vitest file beside the module, and `go run ./tools/webshot -app next -screens <id> -out <dir>` renders it. `PanelHost` draws nothing for a panel id nothing registers, so `internal/web/ui/src/app/panels.test.ts` pins that every `PanelId` has a panel once `@/panels` is imported, and a new id without its `definePanel` fails it.

## How the desktop composes the panels

From 1024px wide `AppShell` (`internal/web/ui/src/app/shell.tsx`) draws the lazy `DesktopShell` (`internal/web/ui/src/desktop/DesktopShell.tsx`) instead of `PhoneShell`, by `useLayout()` (`internal/web/ui/src/app/viewport.ts`): `phone` under 1024, `desk2` from 1024 to 1279 and `desk3` from 1280, read from `matchMedia`. Pairing and the splash with no snapshot stay in the phone's column at any width, and the full mockup draws alone. Routes do not change: the hash names the middle's panel on both frames, and a push link opens the same view.

The frame is `TopBar` across the window (the link pill, `loom@host`, the workspace filter, the three group counts and the fleet's links), then `Sidebar` (the fleet's groups, hidden on the fleet route `#/`, where the middle draws the fleet body in full), the middle, and, at `desk3` on a session route, the `Inspector`.

The middle is the phone's frame for the route: `PanelHead` (the panel's Head, the session's tabs and its Strip, exported from `internal/web/ui/src/app/shell.tsx`) pinned above a scroller, with the panel's Body inside the scroller under `ScrollPaneProvider` with `elementPane(scroller, null)`. The inspector draws the session's tab strip minus the tab the middle lights, and the chosen tab's Body through `PanelHost` with `{ sessionId, params: { id }, search: {} }`, in its own error boundary and scroll pane. `inspectorTab` picks the tab; the choice, with the sidebar's and the inspector's visibility, is kept in localStorage `loom.desktop` (`useDesktop` and `DESKTOP_KEY`, `internal/web/ui/src/app/desktopState.ts`), and anything unreadable there is the default.

A panel is written once: registering it with a `tab` gives it a middle on the phone and on desktop and a place among the inspector's tabs, which is why its Body takes its session from its props and scrolls through the pane (the rules are in `internal/web/ui/CLAUDE.md`). The top bar, the sidebar and the inspector's strip are chrome, not panels. `askConfirm` draws a Drawer on the phone and a centred Dialog on desktop, and the `Toaster` sits top-centre or bottom-right; `AppShell` mounts both once, above the two frames.

## Adding a command

`defineCommand({ id, title, icon, offline, key, when, confirm, run })` in the panel's module, or for a session's actions in `internal/web/ui/src/commands/` (`session.ts`, `asks.ts`, `jobs.ts`), which `internal/web/ui/src/commands/index.ts` imports and `main.tsx` imports in turn (a test that draws a `CommandButton` imports it too); `when` reads only the session's status and group, its `claude` flag, the route and the link state (the group is how a Recoverable or unstarted Ready session is told from a started Ready, as `sessionActions` in `internal/web/ui/src/commands/session.ts` does for every session command); `offline` only for an action that must work without the daemon (the switch; pairing, which runs before any snapshot exists; and the two palette view toggles, which change only this browser's layout); `confirm` for anything that can lose work, naming exactly what happens: it returns a `ConfirmSpec` (title, body, action, destructive, and an optional `field`, a `TextField` whose `max` is in UTF-8 bytes and past which the sheet disables the action and shows `tooLong`, or a `ChoiceField`, a native select with its first option chosen), or null to run with no sheet (an Allow whose suggestion does not persist, a Merge with no other session); `run(ctx, args, input)` calls `api.<client>(…)` and hands the outcome to `showOutcome(outcome, what)`, `input` being the field's value (`""` with no field); `key(args)` for a command whose args pick the thing it acts on (a job, an ask): the in-flight key is the command's id, the session's id and what `key` returns, so Pause on one job does not block Pause on another, and `useCommandBusy(command, ctx, args)` and `CommandButton`'s `args` read the same key; the request path toasts a response's notices itself (`onNotices`, Kill's and Resume's stash notices always) and `showOutcome` toasts only a non-ok outcome; draw it with `<CommandButton id=… />`; a Vitest case for `when` across statuses, groups and link states, and for a command that skips its sheet or holds a field, both sides of it (a sheet's yes with `""` and with a value, a `confirm` that returns null and one that returns a spec). A command off a session route (new session, turning push on, a device setting, quick replies, unpair, pair) has `ctx.session` undefined, so its `run` reads its args and the store and never the session, and its `when` reads `ctx.panel` (`device.pair` is `when` the panel is `pair`, `push.enable` `when` it is `settings`) rather than a session's status; `runCommand` reaches an unsheeted command's `run` in the tap's own task, nothing awaited before it, which is what lets `push.enable` call `Notification.requestPermission()` first, since iOS asks for a permission only inside a gesture. An `offline` command also runs while the snapshot is stale or absent, which every other command does not.

## Adding a palette command

A command appears in the desktop's palette when its `defineCommand` sets `palette: true`, and only when it takes no args, since the palette runs it through `runCommand` with the route's context (`useCommandContext()`) and no args after it closes (`internal/web/ui/CLAUDE.md` holds the rule). A command whose args a view picks (an ask's answer, a job's controls, a send) never sets it. The palette draws the command's `title` (a function title is called with the context), lists it on an empty query only when its `when` holds for the route's command context, and draws it dimmed and inert when `commandEnabled` refuses it (its `when` fails, or the snapshot is stale and it is not `offline`), so `when` and `offline` are written for the button and the palette reads them as they are; no key is shown beside it, since the keys are not in the app. Add the command's id to the set `internal/web/ui/src/commands/palette.test.ts` pins (the case `the palette lists exactly these ten commands`, which fails on an id added or dropped without it; rename the case with the new count, and change the title `internal/web/ui/CLAUDE.md` cites in the same commit, since the lint does not check a TypeScript case's title). A command that changes only this browser's layout lives in `internal/web/ui/src/commands/view.ts` and is `offline`, and a command the phone never needs is imported by the module of the desktop chunk that needs it (`view.ts` by `internal/web/ui/src/desktop/DesktopShell.tsx`), never by `internal/web/ui/src/commands/index.ts`, since the entry's imports are the phone's first load and `TestDist_FirstLoadIsWithinBudget` reads them. Test it as the palette's other commands are tested: the command's own cases beside its module, and the set above.

## Adding a palette place

A place is a row of the palette's Places group, built in `paletteGroups` (`internal/web/ui/src/desktop/palette.ts`, pure, no React) in this order: the current session's tab panels, then Fleet, New session, Flows (only while `hasShownFlows` in `internal/web/ui/src/fleet/groups.ts` holds, the rule of the top bar's Flows link) and Settings. A panel registered with a `tab` is a tab place with no edit: `Palette` hands `paletteGroups` the session's `sessionTabs`, and the place's title is the tab's label, its hint the session's title, its link `hrefFor(<panel id>, { id })`. A place that is not a tab (a new top-level panel with a URL) is one more entry in the plain places' list of `paletteGroups`: a key `place:<panel id>`, a title, an empty hint and `hrefFor("<panel id>")`, written with a case in `internal/web/ui/src/desktop/palette.test.ts` beside `with an empty query lists the session's tabs, then Fleet, New session, Flows and Settings`, which names the order and fails on an entry added without its case. A place that only some fleets have (Flows is the example) states its condition in `paletteGroups` and in a test that leaves it out.

## Adding a read

A read a view draws goes in `internal/web/ui/src/api/reads.ts`, never in the component: a hook over `queryClient` that calls `api.<client>(…)` through `unwrap` and holds what it read in the query cache under a key of the session (and the agent or job), so two components with the same key share one held state and one poll, and an unpair's `queryClient.clear()` drops it. Port the classic app's refresh rule from its module under `internal/web/static/js/` (turns, changes, job), and keep it: one request in flight, with a load asked meanwhile run once when it lands; `retry: false`, because a poll or the view's own retry button is the next attempt; a poll through `refetchInterval` only while the screen says `live` (TanStack pauses it while the page is hidden); a merge by the classic rule (`mergeTurns`, `appendLog`), tested as a pure function beside the hook. Bound what outlives its reader: `gcTime`, `KEEP_SESSIONS`, `KEEP_JOBS` and `KEEP_FLOWS` (the least recently opened is evicted past them) and `MAX_LOG_CHARS` (the log's length in UTF-16 units, trimmed at the next newline); a new read decides its own bound and writes it as a constant beside them. A 409 or a 504 on a read has a meaning the classic screen words ("This job is no longer in the queue."): keep its text and its effect on the polling. Test it in `internal/web/ui/src/api/reads.test.ts` over a stubbed `api`, with a fake clock for the polls, and give webshot's canned loom the route's fixture (`tools/webshot/canned.go`; a screen sends no request the canned loom cannot answer). A read keyed on what the stream changes (the board, read again when the JSON of the session's `flows` changes, `flowKey`) or held for the page's lifetime (launch defaults, never read again when the stream comes back) states its trigger in its test, as the polled reads state their intervals.

## The dev loop

`go run ./tools/webshot -serve 127.0.0.1:5670` serves the canned loom's API (no daemon, until killed); `cd internal/web/ui && pnpm install --frozen-lockfile` once, then `pnpm dev` runs Vite with hot reload and proxies `/api/v1` to that address. Run builds, typechecks and tests through `loom job submit -d "<what>" -- sh -c 'cd internal/web/ui && pnpm run check'`. `pnpm run build` rewrites `internal/web/dist/`, which is committed with the source (`pnpm run dist:check` fails on a stale bundle); `go run ./tools/webshot -app next -out <dir outside the worktree>` renders the built app under the real policy. `-device desktop` (1440×900, the `desk3` layout, inspector drawn) and `-device desktop-narrow` (1100×800, `desk2`, no inspector) render it at the two desktop sizes: bare viewports with a desktop Chrome user agent, scale 1, no touch, no bezel, no status bar, and not the phone-only `add-to-home` and `terminal-select`, and they alone render `palette`, the desktop-only screen that presses Ctrl+K once the app is drawn (a phone skips it, and so does `-app classic`, the default); `.github/workflows/web.yml` renders the phone and both. `pnpm dev` in a desktop browser shows the desktop layout at 1024px wide and up, resizing swaps it live. Vitest runs every test at the phone layout (`internal/web/ui/src/test-setup.ts` sets 390px before each test); a test of the desktop frame calls `setViewportWidth(1100)` or `setViewportWidth(1400)` from `@/test-layout` first, since happy-dom's own 1024px window would read `desk2`. Node 22 and pnpm come from the flake's dev shell.

- **Time zone.** Vitest runs with `TZ=Africa/Johannesburg` (`test.env` in `internal/web/ui/vite.config.ts`), so a test of a local-time rendering (`clock` in `TurnList.tsx`) computes its expectation from the `Date`'s local fields and fails under CI's UTC if the component formats in UTC; a test asserting a UTC-looking time passes only where the zone happens to be UTC.

- **Licences.** The build writes each bundled package's and font's licence into `internal/web/dist/THIRD_PARTY.txt`, and `NOTICE.md` points there; a new dependency needs only the rebuild.

## Reading the budget test's failure

`TestDist_FirstLoadIsWithinBudget` reads the committed `internal/web/dist/` (build first), and fails with `first load is <n> bytes gzipped, over the <budget> budget:` and each counted file with its gzipped size, one a line. The files are the entry script and the `modulepreload`s of `internal/web/dist/index.html`: find which import pulled the heavy one into them and load that screen through a dynamic `import()`; raising `firstLoadBudget` (`internal/web/static_budget_test.go`) is the owner's call.

## Changing the classic app

The classic app is frozen until cutover (only the Settings row, its worker registration and its worker's shell fetch and cache cleanup change); the new app's source is `internal/web/ui/`, its rules are in `internal/web/ui/CLAUDE.md`, and the sections above give its procedures.

- Modules are `.mjs` (Node 22's `node --check` catches syntax errors in those and misses them in `.js`): `for f in internal/web/static/js/*.mjs; do node --check "$f"; done`. CI has no Node, so no Go test depends on it.
- No inline script and no `style` attribute: the Content-Security-Policy is `default-src 'self'`, and a blocked handler fails silently on the phone.
- The Preact + htm module is one pinned file, `internal/web/static/lib/preact-htm.mjs`: replace it and its pinned SHA-256 together, with the version and source URL in its header comment and the licence in `NOTICE.md`. It sits in `lib/`, not `vendor/`, because Go's module zips drop files below a nested `vendor/` and a `go install` build would embed nothing.
- `sw.js` carries the placeholders `__LOOM_BUILD__` and `__LOOM_SHELL__`, and `index.html` the build ID in its `loom-build` meta tag (`__LOOM_BUILD__`); `routeStatic` fills them when serving; the precache list therefore follows the embedded files, and the worker caches the shell only, never `/api/`.
- The skin is dark only, its tokens on `app.css`'s `:root` (`TestStatic_TheSkinIsDarkWithEveryToken`). A form control's text is 16px: iOS zooms into a smaller one.
- Claude's text is drawn from its tree (each text item of `GET /api/v1/sessions/{id}/turns`), never from an HTML string; a thinking item's `text` is drawn as a text node. `GET /api/v1/sessions/{id}/message` stays but no screen draws the last message now. A node the app needs is added in `internal/web/markdown.go`, with a case in `TestBuildTree_EachNodeType`.

## Answering an ask

The dialogs a session's Claude holds open (`InstanceView.Asks`, `core/asks.go`) reach the phone through the loom mod: it posts each ask to the mod socket and polls for its answer while Claude's own dialog stays up (spec `docs/superpowers/specs/2026-11-03-pwa-answer-asks-design.md`, whose Outcome records what Claude does). What to keep when changing any part of it:

- **The model composes, the mod returns.** `Core.Answer` checks the answer against the ask and builds Claude's exact `result`, `deny` or `decision` (`composeAnswer`); the route only bounds the body, and the app only fills it. A shape Claude refuses is a hook Claude skips, so the dialog stays up and the phone was told it worked.
- **The Reply comes when the mod takes the answer, not when the model stores it.** An answer no poll takes within `askTakeTimeout` is withdrawn (`askTick`) and refused, so a late poll never delivers what the phone was told failed; one whose ask closes first is refused "answered in Claude first".
- **An ask closes when Claude's dialog answered it:** the mod's close (a question's `next` resolved; a permission's paired call settled), or for a main-loop permission the session leaving Prompting after the model saw it Prompting with the ask open (`asksSeeStatus`'s `seenPrompting`). A permission hook's `next.signal` never aborts on a person's answer, and the roster reads `busy` while a background agent's prompt waits, so a subagent's permission closes only with its call. A closed ask leaves a tombstone on its link: the mod posts again on a 404, never on a 410.
- **Every refusal reaches the phone as 409 with the model's words.** Only three errors keep their identity across the wire, so the route can't tell an answered ask from a malformed answer.
- **Changing the module means the opt-in real-Claude runs:** `TestRealClaude_ValidatesTheMod` and `TestRealClaude_AnswersAsksThroughTheDaemon` (`LOOM_TEST_REAL_CLAUDE=1`); nothing in CI loads the mod.

## Details moved out of CLAUDE.md

What `internal/web/CLAUDE.md` once spelled out inside a rule, kept here so the rule stays short. Each bullet names the rule it belongs to.

- **The guard:** a bare `localhost` or an IP is never an accepted Host because its cookie reaches every local port; the cross-site post `guard` refuses is a method but GET and HEAD without an accepted `Origin`.
- **The mockup route:** it is only an iframe's `src`, so a JSON error would show as raw text in the app's frame; its failures are pages (`writePage`).
- **The rebind:** every `ConfigureWeb` bumps `Rev` and nothing else does, so a disable and an enable that one `Sync` coalesces into a single `ModelChanged` (the settings already bound) still rebind, a retry with the very values that failed still binds, and the layer's own report does not end every open stream by rebinding.
- **The panic stop:** `fail` returns at once and runs the one stop `Close` also runs, on a goroutine of its own, so a part may call it from the goroutine the stop waits for.
- **The route table:** the adapter owns decoding, statuses and the log line of a typed handler.
- **A refused action:** the app's buttons only follow the session's `status` and `group`.
- **A read route:** up to `maxReqs` tracked requests are kept for `reqKeep` each.
- **Notices:** the daemon also hands a notice tied to the web client's request to its other clients, or keeps it for the next TUI, since the phone may never see it.
- **The stream:** the ping is every `pingEvery` (20 s) and each event's write is bounded at `streamWriteTimeout` (30 s).
- **Push triggers:** within one Prompting stretch the layer pushes again only for a non-empty reason or tool summary that differs from the last non-empty one pushed, since a cleared or returning label is the same prompt and each push alerts the phone again. A turn's stop verdict (`VerdictStop`) is pushed at most once and never for a turn that ended before the workspace's baseline: `needs_you` as waiting, `done` as done (under the device's finished toggle), and a finished push the Running→Ready edge owed only for `stopped` or no verdict.
- **Escalations:** an escalation is a `Watch.Escalations` entry the workspace's last projection lacked, identified by its issue and recorded time (`escalationKey`).
- **The push sender:** the timeout is 10 s, at most 30 pushes a minute per device, and the queue holds at most 100.
- **The message route:** `GET /api/v1/sessions/{id}/message` stays but no screen draws the last message, so a screen that does must draw its tree too.
- **The device cookie:** its lifetime is `cookieMaxAge`.
- **Reporting to the host:** `TestApplyWeb_OnlyWhatTheLayerDidIsReportedOff` calls `applyWeb` with a recording host; `TestApplyWeb_AWebJSONTheModelLeftAloneKeepsItsReason` pins the same through a real model.
- **The sinks:** a sink that blocks stalls the drain, so the client's queues grow.
- **The cookie's token:** hashing the cookie's text on one side and the bytes on the other makes every route answer 401 with nothing logged.
- **The daemon's stop:** closing the layer first also keeps every request of a phone from reaching a loop that is quiescing.
- **The trees:** both apps share one origin.

## Traps

- **The mockup route is an iframe's page, not JSON.** `GET /api/v1/sessions/{id}/mockup` is the one route with its own CSP (`mockupCSP`, a sandbox) and HTML failures (`writePage`); the app learns that a companion stopped from the session's `mockup` going null, not from the frame, whose page it cannot read. A companion is found only when the brainstorming skill started it with `--project-dir` on the session's worktree, and only at a hand-back event or a read (`core/mockup.go`). Its policy's `sandbox` gives the page an opaque origin, yet Chromium still lets `frame-ancestors 'self'` match the app (webshot frames its canned page under the same policy); Safari's behaviour is the iPhone checklist's to confirm. The skill's stop script kills the companion without its shutdown marker and deletes `state/server.pid`, which is why `mockup.Find` requires that file; `TestRealCompanion_FindAndFetch` (opt-in) runs the skill's real scripts.
- **A field added to what the model publishes is a wire change.** `WebView` rides `ModelChanged`, and `InstanceView` carries `github.State` and the rest, so a new field there needs no `rpc.Protocol` bump but changes `docs/specs/protocol.md`: rerun `go test ./core/rpc -run TestProtocolReference -update`, or `TestProtocolReference` fails the suite (and the Nix build). Keep nil and empty apart only if both survive JSON: a nil slice crosses as `null`, an empty one as `[]`.
- **iOS keeps a Home Screen app's storage apart from Safari's, and sends Web Push only to Home Screen apps (iOS 16.4 and later).** A pairing done in Safari does not carry over to the installed app.
- **Every request is checked against the origin set.** The set is the configured origin plus, for a listener bound to `127.0.0.1` or `[::1]`, its local origin `http://loom.localhost:<port>` (`core.LocalOrigin`; `loom web open` opens it). The `Host` must be a member's host and port (421 otherwise), and a request other than GET or HEAD must carry exactly one `Origin` equal to a member (403). Bare `localhost` and the IP literal are never members, since a device cookie set there would reach every server the browser reaches there on any port, and a listener on another loopback address has no local origin. Each origin holds its own device cookie, so a browser on the local origin and one on the tunnel are two devices. The `loom.localhost` cookie is host-only, but cookies ignore the port: a hostile listener on another loopback port (another OS user's server, a forward to a compromised machine, a container's published port) that steers the browser to `loom.localhost:<its port>` receives it, and the pairing code `loom web open` mints is its opener's argument, readable from the process list while the opener or a freshly started browser runs. Both are accepted on a single-user machine. A test that builds its own request sets both headers.
- **Pairing codes live in the model's memory.** A daemon restart voids them, five wrong codes void every pending one, and a code is bound to the device name it was made for.
- **A `web.json` that fails to load is never overwritten.** Unreadable, a newer version, or a stored `listen`, `origin`, device name, token hash or VAPID key that fails validation all count. The web stays off, `ConfigureWeb`, `RevokeDevice` and `SetWebTerminal` refuse, `PairDevice` answers that the web is off, and a notice says why; fix or move the file by hand.
- **A push service answers 201 to any ciphertext it accepts and cannot read it.** A wrong encryption shows only as a phone that stays quiet, which is why `internal/web/webpush` is checked against RFC 8291's own example.
- **Cloudflare terminates TLS, so it can read the traffic and the device token.** Revocable tokens limit the damage; never log a token, cookie, pairing code or push subscription.
- **The layer holds no session state.** A copy of a view that outlives its replica goes stale: derive from the client's replica and the model's device records.
