# The work queue (the model's side of `loom job`)

**Read this when** you change `core/queue*.go`, `gateQueue`, `adoptJobs`, a job's notice, or `sched`'s runtime (the shim, the lock probe, group signals, the usage sampler).

**What it is.** The daemon's model owns a per-host queue of jobs that sessions submit with `loom job`. It admits each against the caps in the global `config.json`'s `scheduler` block, starts it as a detached `loom job-shim` (a child in a session of its own, so it outlives the daemon), watches it through the shim's lock, and tells the owner's Claude when it ends. The pure half (types, caps, first-fit admission, the `jobs.json` store, the per-job file codecs) and the process half (the shim, the lock probe, group signals, the sampler) are the `sched` package; the queue's state and decisions are `core/queue.go` (state, load and save, boot adoption, retention), `core/queue_admit.go` (admission passes, starting), `core/queue_watch.go` (the gated job's lock tests, sampling, settling, a cancel's escalation), `core/queue_ops.go` (the operations the requests wrap), `core/queue_notice.go` (notices) and `core/queue_beliefs.go` (signatures, sizing, `beliefs.json`). The gate is `gateQueue` in `core/gate.go`, 3 s; [`adding-a-gated-job.md`](adding-a-gated-job.md) covers the gate's own traps.

## Rules

1. **Test the lock before you signal a group.** A job's process group is its shim's pid. Send a signal (`sched.SignalGroup`) only to a group whose `sched.Probe` shows `run.lock` held, which proves the pid is still the shim. The exceptions are a lost job (the shim is gone and left no `exit.json`) and the shim of a failed start (`queueState.silent`) once it is gone: the group gets SIGKILL only when the latest `ps` sample shows processes in the group and none with the shim's pid. A live process with that pid and no lock is a reused pid, and its group is never signalled. *Silent:* a signal to an unrelated process group (your shell, an editor, another job). Convention only; a test that proves a signal is withheld needs a reused-pid fixture.
2. **Settle before you admit, at boot.** `Model.Boot` loads `jobs.json` (`loadQueue`), whose last steps are `adoptJobs` and then the first `admitJobs`. `adoptJobs` runs one lock pass over every running job (and every job the record calls queued, since a start whose save failed leaves a running shim behind a queued record), before the loop starts. `Model.Begin` then calls `maybeQueue`, which hands the adopted running jobs to `gateQueue`'s watch. The caps count the jobs adopted, and nothing runs twice: a held lock means running, an `exit.json` means settle from it, neither means `lost`. A queued record whose lock test failed is held out of admission (`queueState.unprobed`) and tested again (`reprobeHeld`) before each pass. *Silent:* an admission pass before settling starts jobs on top of ones already running.
3. **The queue is touched only on the loop.** `queueState` is read and written by the model's goroutine; a job (the start, the sample) gets a snapshot (ids, paths, pids) and returns one result that `Deliver` applies. A result lands after the job it names may have been cancelled or removed: look the record up again before acting. *Silent:* a race that only `CC=clang CGO_ENABLED=1 go test -race` finds, and only when a test overlaps it.
4. **Remove a job's files only through `sched.RemoveJobDir`.** It removes `JobDir(dir, id)`, built from the ID; never a path read from `jobs.json`, `spec.json` or the wire. It has two callers: retention, which drops finished jobs beyond `keep_finished`, oldest end first, once `jobs.json` no longer lists them (`removeJobDirsJob`), and `submitJob`'s take-back of a directory it has just created, when a later write fails. `submitJob` creates the directory exclusively (`sched.CreateJobDir`): one that already exists refuses that submission and is left as it is, and `NextID` moves past it in memory (not saved at that point, so the next submit tries the next ID, not this one again; `sched.LoadStore` also raises `NextID` past every numeric `jobs/<id>` on load), so a job never takes over an old job's `output.log`, `exit.json` or lock. *Silent:* a recursive delete of whatever a corrupt file names, or a new job reading an old one's result.
5. **Leave a `jobs.json` that fails to load alone.** An unreadable, invalid or newer-version file (`sched.ErrNewerStore`) sets `queueState.loadErr`: submissions are refused with the reason, admission pauses, a notice is raised, and the running shims carry on. Never write over it, and never start from an empty queue. Write the store only through `sched.SaveStore`. The same goes for `config.json`: `refreshPolicy` reads only the `scheduler` block (`diskSchedulerBlock`), and a file it cannot read pauses admission with `config.json could not be read: <err>` and is left where it is, never loaded through `config.LoadConfigFrom`, which would rename it aside and fall back to the host's defaults. *Silent:* an overwritten file loses every queued job and the ID counter, and IDs are reused; a quarantined `config.json` swaps the owner's caps for the defaults.
6. **A write that fails is not a lost change.** A request that cannot write `spec.json` or `jobs.json` is refused with the error and changes nothing; `setSchedulerCaps` reads `config.json` through `readGlobalConfig` and refuses on any read or decode error (`config.json could not be read, so the caps were not saved: …`), leaving the file byte for byte as it was. A change the model made on its own (a start, a settle, a usage peak) stays in memory, raises a notice and is written with the next save.
7. **Never paste a notice.** A job's end goes to the owner's Claude through the loom mod's outbox (`OriginJob`). With no live mod, or an owner that is not running, the notice is recorded on the job as undelivered, with the reason. A paste into the pane could answer an open dialog. A pause, a kill or a reset someone requests cancels the session's jobs first (`cancelOwnerJobs`; `Reset` calls it for every session of the workspace) and sends no notice; a pause the daemon makes on its own for a session whose tmux session died (`pauseGone`) leaves its jobs running, since a dead pane is nobody's choice to drop the work.
8. **Fail closed.** A cwd that is gone at start fails the job ("its folder is gone"); a shim that writes no `started.json` within 5 s fails the job, and its group is sent SIGKILL only once its lock proves the shim alive: until then `queueState.silent` keeps the pending kill, which `gateQueue` sends when a later lock test finds the shim alive and drops when no process has its pid any more, or after 10 minutes; a `ps` sample that fails or times out is skipped and the lock tests go on without it. Nothing is guessed.
9. **Size from the belief, live, and learn only from what ran.** `submitJob` resolves the job's signature with `sched.FindRepo` (git's files only: it runs on the loop, so never add a git subprocess there), sizes its claim with `sched.Size` from its belief (`sizeRecord`), and marks the belief seen once the job is stored. Every admission pass re-sizes the queued jobs this build sized (`resizeQueued`, before `sched.Admit`): a claim stays live until the job starts, and a record queued by a build before sizing (no `Sources`) keeps its claim. `settledJob` records the run (`recordRun`, through `sched.RunOf`); `adoptJobs` and `noteAlive` mark a job `Adopted`, so its partly sampled peak counts only as a floor. A `beliefs.json` that fails to load sets `beliefsErr`: learning is off, jobs take their flags and the default claim, nothing is recorded, and the file is never written (`saveBeliefsQuiet` checks). *Silent:* a git subprocess on the loop stalls every client; a floor taken as a full peak teaches a failing build's small peak to the next good run.

## The advisor

`core/queue_advisor.go` runs the scheduler's agent (`sched/advisor`). `submitJob` marks a job `asking` when `askForPrior` holds (the advisor is available, `sched.NeedsPrior`, and the signature's last prior didn't fail in the last 10 minutes) and queues a prior (`queueAdvice`; jobs of one signature share one call). `dispatchAdvisor` keeps one call in flight, priors first; it drops a call while the advisor is off (`advisorOff`: learning off, the block invalid or off, no Claude program, an unregistered account, the 30-minute pause after three failures) or its account's 5-hour window is at 90% (`advisorUsageHigh`), releasing the jobs that waited. `deliverAdvisor` stores a checked prior (`priorOf` copies a `like` belief's learned parts) or a note, and releases the jobs; `admitJobs` releases a job that has waited `wait_seconds` (`releaseOverdueAsks`), and `loadQueue` asks again for jobs a previous daemon left asking (`resumeAsks`). `recordRun` scores a prior (`sched.ScorePrior`) and queues a reconcile on a surprise (`sched.Surprise`), at most once per belief in six hours. Tests run a fake `claude` script through `SetAdvisorForTest` (`core/seams.go`); with no Claude program (`NewForTest`'s default) the advisor is off, so no test reaches a real model.

`queueView` adds each job's usual duration, P90 and overdue mark from its belief (`sched.Usual`, `sched.OverdueAfter`) and each queued job's forecast start (`sched.Forecast`, with `hostUsual` for jobs with no estimate). `ReadBeliefs` answers from the registry with copies (`Belief.Clone`), and refuses while learning is off; `ForgetBelief` writes `beliefs.json` before it answers (a failed write keeps the belief) and gives queued jobs of the forgotten signature a new, empty belief.

## Testing with real shims

A test binary has no `job-shim` command, so a package whose tests start real shims (`sched`, `core`, `internal/cli`) re-executes its own test binary as the shim:

- Its `TestMain` calls `sched.MaybeRunTestShim()` as its first statement. When the environment variable `sched.ShimTestEnv` (`LOOM_SCHED_TEST_SHIM`) is `1`, the process runs `sched.RunShim` on its last argument and exits instead of running tests.
- The runner a test hands the model is `sched.TestRunner()` (the test binary, with that variable set), installed with `Model.SetJobRunnerForTest` in `core/seams.go`.
- Real jobs are short commands (`sh -c`, `sleep`), and every test leaves no process group behind: cancel or wait for each job it starts.
- Build fixtures through the production path: a booted model, a real shim, a `jobs.json` written with `sched.SaveStore`. A fake runner skips the lock, the `Setsid` and the `exit.json`, which is where the bugs are.

## Traps

- **A `TestMain` without the hook.** The shim child is the test binary with the variable set; without `MaybeRunTestShim` it runs the whole suite, whose tests start more shims. Add the hook to a new package's `TestMain` before its first real-shim test.
- **Environment.** The job's environment comes only from `spec.json`; the shim process itself gets the daemon's environment plus `Runner.Env`. Do not build a git or tmux command from a job's environment.
- **The sample is a hint, not proof.** Usage and the lost-job rule read one `ps -A` snapshot; procps and BSD format `time` differently and `ParsePS` reads both. Skip a failed sample, never reuse a stale one for the kill rule.
- **`KillMode`.** Under systemd's default `control-group`, restarting the unit kills every shim in its cgroup. `USAGE.md`'s unit sets `KillMode=process`; a report of "jobs die with the daemon" on a unit without it is not a model bug.
- **Windows.** The runtime's stubs return `sched.ErrUnsupported` and `SubmitJob` refuses with it. After touching `sched`'s platform files, run `GOOS=windows CGO_ENABLED=0 go build ./...` and the same for `darwin`.
- **The queue's published view follows more than the records.** `QueueChanged` is also published when a job's owner resolves differently (a rename, an unregister, a kill), so `JobView`'s owner fields stay current; a change to the queue that never calls `q.moved()` is never published.
- **`loadQueue` ends with an admission pass.** A seeded queued job that fits starts at load, so a test that wants jobs left queued uses an over-cap claim or a paused policy block.
- **A cap edit never touches running jobs.** It changes only what starts next; an `--exclusive` claim is stored as a flag, so it follows the caps it is admitted under.

## What the gates won't tell you

- Whether a new signal path tests the lock first (rule 1): no test fails when one forgets.
- Whether a new write of the queue's files goes through `sched.SaveStore` and the codecs.
- Whether a real-shim test leaves a process running after it ends.
