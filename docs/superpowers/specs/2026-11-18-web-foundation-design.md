# Loom web: the foundation

Date: 2026-11-18. Branch `aidanb/loom-professional-web`. Sub-project 1 of the web programme. The web layer's route table and a contract generator, a new app beside the classic one, CI; no Core request, no wire change, no `rpc.Protocol` bump, and the JSON under `/api/v1` keeps every field it has.

## Problem

The owner wants loom web "more professional": a desktop view, a robust and extensible architecture, a phone app that is easier to use, perhaps a component library, and eventually a web app that supersedes the TUI. Today's app (Findings) is a hand-built monospace skin of the TUI, with no types, no JavaScript tests and no build, whose JSON contract is written by hand on both sides. It cannot grow into a desktop app or a TUI replacement without a foundation. This spec is that foundation: the same screens with the same behaviour, rebuilt on a typed, component-based stack in a new visual direction.

## The programme

Decided with the owner on 2026-11-18, in this order, each sub-project its own spec, plan and build:

1. **Foundation** (this spec).
2. **Phone usability:** navigation, gestures, the owner's pain points.
3. **Desktop:** a multi-pane workspace, keyboard and a ⌘K palette, how a desktop reaches the daemon.
4. **TUI parity series:** a live terminal first (xterm.js, pane bytes relayed by the daemon over a WebSocket of its own, separate from the event stream; full input on the desktop, mostly reading with an input bar on the phone), then settings, accounts and workspaces, the host's work queue, feedback threads, the review pane, the issue watcher, and user commands, until the TUI is optional.

Decisions that shape this spec:

- **Visual direction B, "modern dev tool"** (chosen from three mockups, `docs/superpowers/specs/2026-11-18-web-foundation/visual-direction.html`: refined terminal, modern dev tool, native iOS): a sans-serif UI in the manner of Linear, Vercel or GitHub, monospace only for code, commands, branches, paths, diffstats and logs, soft cards and tinted pills, amber still marking what needs the owner.
- **The web will carry a full terminal**, so the app's panels must admit a terminal panel and the transport must admit a WebSocket beside the event stream. Neither is built here.
- **"Extensible" means developer registries plus user commands:** panels, commands and routes each register in one place, and every action is a named command. The ⌘K palette and key bindings (Desktop) and the owner's Lua scripts' actions (Parity, once the script engine moves from the TUI into the daemon) reach the same command registry. No third-party UI plugins.

## Findings

From the repo at `14500558` and the dev machine, 2026-11-18:

- **The classic app** (`internal/web/static/`): Preact and htm in one pinned file (`static/lib/preact-htm.mjs`, SHA-256 in `TestPreactHTM_IsThePinnedFile`), 30 ES modules (about 4,900 lines) and one 898-line `app.css`. No build step, no types, no JavaScript tests; modules are checked with `node --check` only, and a rule keeps logic in Go. Routes are hash routes (`#s/<id>`, `#s/<id>/info`, `#s/<id>/diff`, …, `parseRoute` in `js/app.mjs`), and pushes open `/#s/<id>` or `/#s/<id>/mockup` (`internal/web/triggers.go`).
- **The web layer** (`internal/web`, about 4,500 lines of Go): `routeAPI` (`internal/web/api.go`) registers 23 authed routes one `m.Handle` at a time, each wrapped in `l.authed` by hand ("every route uses `authed`" is a Convention); `POST /api/v1/pair` is open; the stream, push key and static routes register elsewhere. The JSON types (`sessionJSON`, `snapshotJSON`, …) are Go structs documented in prose in `internal/web/README.md`; the app reads them untyped.
- **Coverage:** the layer calls about 25 of `core.Core`'s 92 methods. Against the TUI it lacks the live agent pane and the worktree shell, workspace, account and settings management, the host's work queue, feedback threads, the review pane, the issue watcher and the keymap. The TUI's user extensibility is the Lua engine (`script/`), which owns the keymap and lives in the TUI process; the owner's one script, `~/.loom/scripts/open_emacs.lua`, binds `e` to type `emacs <worktree>` into the terminal pane.
- **Serving:** `buildStaticAssets` (`internal/web/static.go`) embeds `static/`, fills `__LOOM_BUILD__` into `index.html` and `sw.js` and `__LOOM_SHELL__` (every embedded file's URL) into `sw.js`, and refuses a file whose extension is not in `staticContentTypes`. The CSP is `default-src 'self'`, which drops inline scripts, `<style>` elements and `style` attributes written as markup (a property set through the CSSOM, as React does, is allowed). The device cookie is `__Host-loom`. The classic worker caches the shell under `loom-shell-<build>`, deletes other `loom-shell-` caches on activate, and keeps the snapshot in IndexedDB database `loom`.
- **Builds:** Nix builds loom with `buildGoModule` from vendored modules, with no Node, and its check phase runs the Go tests; the dev shell has no Node either. CI has no Node (`.github/workflows/build.yml`, `race.yml`, `lint.yml`, `e2e.yml`, `docs.yml`, `flow.yml`, `release.yml`). The dev machine has Node 22.23.3, pnpm and bun.
- **webshot** (`tools/webshot`) serves `internal/web/static/` from disk against a canned loom (`tools/webshot/fixture/*.json`), drives headless Chromium over a pipe (the first of `chromium`, `chromium-browser`, `google-chrome`, `google-chrome-stable` on PATH, or `-browser`), renders each screen as an iPhone 15 Home Screen app, and exits 1 on a console error, an uncaught exception or an API route the fixture can't answer.
- **shadcn/ui**'s CLI v4 (March 2026) initialises on Base UI (its recommended base), React Aria or Radix (`shadcn init --base`), with Tailwind v4 configured by `@import "tailwindcss"` and the `@tailwindcss/vite` plugin.
- **Budgets:** root `CLAUDE.md` is at 15,892 of 16,000 bytes; `internal/web/CLAUDE.md` at 17,958 of 20,000.

## Decisions

### Scope and migration

1. **In scope:** a new app in `internal/web/ui/`, built to `internal/web/dist/`, with every classic route ported in direction B with the classic behaviour: the fleet, a session's conversation (turns, thinking, agent links, fact strip, needs-you box, asks, reply box with quick replies and slash commands), info (tiles, agents, jobs, actions), changes, mockup and full mockup, the subagent screen, the job screen, the flow board, row and document screens, the host's flows, new session, settings, pairing and Add to Home; the pinned header with the session tabs, the footer status row, toasts, confirmation sheets, push setup and the subscription check, the Home Screen badge, stale and offline states, service-worker updates and the cached snapshot. Plus the route table and generator (§16–§19), the panel and command registries (§22–§23), Vitest, and the `web.yml` workflow.
2. **Out of scope:** changes to phone navigation and gestures (Phone), the desktop layout and the ⌘K palette (Desktop), the terminal and every new feature (Parity), and a light theme: the app is dark only, its tokens arranged so a light set drops in later (§30). On a wide screen the new app shows its phone column centred, as the classic one does.
3. **Both apps are embedded side by side, and a per-device cookie picks one.** `routeStatic` serves the shell files (`/`, `/index.html`, `/sw.js`, `/manifest.webmanifest`) from the new tree when the request carries `__Host-loom-ui=next`, and from the classic tree otherwise (no cookie, `classic` or anything else); any other path comes from the selected tree, else from the other one, so a page loaded just before a switch still gets its assets. Shell answers carry `Vary: Cookie`. The cookie holds no data: it is `Secure; Path=/; SameSite=Strict; Max-Age=31536000`, not HttpOnly, and set by the app.
4. **The switch is a command in each app's Settings:** "Try the new app" in the classic one (its only change besides §5's registration line and §6's cache cleanup) and "Back to classic" in the new one. It sets the cookie and registers the worker again at `/sw.js?ui=<app>` (§5); the other tree's `sw.js` differs in bytes (its shell list), so the browser installs it, the worker takes over (`skipWaiting`, `clients.claim`) and the page reloads on `controllerchange`, the path a daemon upgrade already takes. The Home Screen app keeps its origin, its `__Host-loom` pairing and its push subscription, which belongs to the registration and survives a change of script. Offline, the cookie is set, the update fails, a toast says the switch happens on the next launch, and the current app stays.
5. **The worker's URL carries the choice too** (owner, 2026-11-18, in place of a spike on the iPhone; widened by the owner the same day after the skeleton review found that a hard-coded `?ui=next` never completes a switch back deferred offline, and that a worker precaching the shell by the cookie alone can cache the other tree's shell): both apps register the worker at every launch, and the switch registers it again, as `/sw.js?ui=<app>`, `<app>` being `next` when the `__Host-loom-ui` cookie is `next` and `classic` otherwise, so a switch deferred offline completes on the next launch (the classic app's registration line changes for this). `routeStatic` answers every shell file (`/`, `/index.html`, `/sw.js`, `/manifest.webmanifest`) by its `ui` parameter when it has one (`next` the new tree, any other value the classic one), else by the cookie; and each tree's worker fetches its own shell files with `?ui=<its tree>` when it precaches or refreshes them, storing each under its plain path, so a worker never caches the other tree's shell whatever cookie its requests carry. The switch so works whether or not a Home Screen app's worker requests carry the cookie, and the iPhone checklist confirms it (Testing); the rest of §3 stands.
6. **Caches and storage stay apart:** the new worker caches under `loom-next-<build>`; each tree's worker deletes, on activate, every `loom-shell-` and `loom-next-` cache but its own. The new app keeps its snapshot in IndexedDB database `loom-next`, so switching back finds the classic snapshot untouched (drawn stale until the stream is back).
7. **A route the new app has not ported yet** draws a placeholder naming the screen, with the "Back to classic" command. None remains once the epic's last part lands (Delivery).
8. **Cutover is the owner's call, inline, after the epic:** once the new app has passed the iPhone checklist and been used daily, one commit makes the new tree the default (no cookie serves it) and a later one deletes `static/`, the switch, the classic-only rules and webshot's `-app classic`.
9. **Done when** every route renders in webshot with no console error, CSP violation or unanswered route; CI's typecheck, lint, Vitest, bundle freshness and webshot steps pass; the Go suite passes; and the iPhone checklist (Testing) passes on the new app.

### Repo layout and build

10. **`internal/web/ui/` is the app's source:** `package.json` (pnpm through `packageManager`, Node 22 through `engines`), `pnpm-lock.yaml`, `vite.config.ts`, `tsconfig.json`, ESLint (flat config: typescript-eslint's `recommendedTypeChecked` and eslint-plugin-react-hooks' recommended rules) and Prettier (its defaults, `printWidth` 100) configs, `src/`, and `public/` (`sw.js`, `index.html`'s icons, the manifest), whose files Vite copies verbatim; Vite also leaves `index.html`'s `loom-build` meta tag alone, so `__LOOM_BUILD__` and `__LOOM_SHELL__` reach `dist/` intact (`buildStaticAssets` refuses a tree missing either). Its scripts are `dev`, `build`, `typecheck`, `lint`, `format:check`, `test`, `check` (typecheck, lint, the format check, Vitest and `node --check public/sw.js`, in that order) and `dist:check`, which builds into a temporary directory and compares the result with `dist/` byte for byte without touching the tree. Stack, at current stable versions pinned by the lockfile: TypeScript, React 19, Vite, Tailwind CSS 4, shadcn/ui components initialised on Base UI, TanStack Router 1, TanStack Query 5, Zustand 5, lucide-react, Vitest with happy-dom and Testing Library.
11. **`internal/web/dist/` is `pnpm build`'s output, committed** and embedded with `//go:embed all:dist` beside `//go:embed static`. `buildStaticAssets` builds each tree's assets as it builds the classic ones today (placeholders filled, the worker's precache list from the tree's own files, unknown extensions refused); `staticContentTypes` gains `.svg` (`image/svg+xml`), `.woff2` (`font/woff2`) and `.txt` (`text/plain; charset=utf-8`). Vite writes no manifest (`build.manifest` off). `.gitattributes` marks `internal/web/dist/**` `linguist-generated=true -diff`, so reviews and session diffs skip the bundle while `git diff --exit-code` still sees it change.
12. **The dev loop:** `pnpm dev` runs Vite with hot reload and proxies `/api/v1` to webshot's canned loom, which gains `-serve <addr>` (serve the fixture's API until killed, render nothing; `127.0.0.1:5670` by default, the address `vite.config.ts` proxies to); no daemon is involved. webshot gains `-app classic|next` (default `classic` until cutover), rendering `internal/web/dist/` for `next`. Builds, typechecks and test runs go through `loom job`.
13. **The dev shell** (`flake.nix` `devShells.default`) gains `nodejs_22` and `pnpm`. The Nix package does not: it embeds the committed bundle, and its check phase runs the Go tests over both trees.
14. **CI:** a new `.github/workflows/web.yml` runs on pushes and pull requests to `main` that touch `internal/web/ui/**`, `internal/web/dist/**`, `tools/webshot/**` or the workflow: `pnpm install --frozen-lockfile`, `pnpm run check`, `pnpm run dist:check` (a stale bundle fails), then `go run ./tools/webshot -app next -out "$RUNNER_TEMP/shots"` (GitHub's Ubuntu runners ship `google-chrome`). `build.yml` adds `internal/web/dist/**` to its paths, so the Go static tests run on a bundle-only change.
15. **The budget:** a Go test sums the gzipped size of the entry script and every `modulepreload` that `dist/index.html` names, and fails above 250,000 bytes. The flow screens, the job screen and the mockup screens are split into chunks of their own (route-level lazy loading), so they don't count against it.

### The API contract

16. **One route table** in `internal/web` declares every route under `/api/v1`: method, path, whether it is open, its log name (the action its log line names today, unchanged), its client name (the generated TS function's), its query type, its body type, its success status (200, 201 or 204), its response type, and a typed handler (`func(ctx context.Context, c call, in T) (R, error)`, `call` carrying the device name and the request's path values). Registration walks the table and wraps every route not marked open in `authed` (`guard` already fronts the whole mux, `internal/web/server.go`); a test pins the open set to exactly `POST /api/v1/pair`. Today's handlers become typed handlers with their behaviour unchanged (`internal/web/api_test.go` and the other route tests pin it); decoding stays `readJSON`'s and encoding `writeJSON`'s and `writeError`'s, and the status mapping (`modelStatus`, the pairing refusals, 202 pending, 504) is unchanged.
17. **The stream gets a table too:** each event's name and payload type (`snapshot`, `sessions`, `workspaces`, `usage`, `quick_replies`, `device`, `notice`, `ping`, `bye`). `GET /api/v1/stream` (server-sent events) and `GET /api/v1/sessions/{id}/mockup` (an HTML page under `mockupCSP`) stay hand-registered, outside the typed table; a path-only entry for the mockup route lets the generated client build its URL.
18. **The generator** (`go generate ./internal/web`, standard library only, like `core/rpc`'s) reads the two tables through an internal registry, takes each JSON shape by reflection over the declared Go types (JSON names from the tags; a field with `omitempty` is optional, `name?: T`; a pointer, slice or map without it is nullable, `T | null`, as encoding/json sends a nil one), and takes string unions from typed string types whose values internal/web lists once beside each type: every field the README documents as one of a fixed set of values (a session's group, a job's state, a step's state, an ask's kind, a flow cell's status, and the rest). It writes:
    - `internal/web/ui/src/api/gen.ts`: a TS type per JSON type, a union per string type, a typed client function per route (path values, query and body as arguments, the response type as the result) and the stream's event map;
    - `docs/specs/web-api.md`: the reference, every route and event with its types, as `docs/specs/protocol.md` is for the wire.
    Each TS type takes its Go type's name without a trailing `JSON`, its first letter upper-cased (`sessionJSON` is `Session`, `sendBody` is `SendBody`), and each client function the route's own client name (§16); two Go types or routes that map to one TS name fail the generator. A test in the generator's package regenerates both files in memory and fails on any byte of difference.
19. **Compatibility is mechanical:** the generator also writes `internal/web/api.fields`, one sorted line per shipped field (`Session.status: SessionStatus`) and per route (`GET /api/v1/sessions/{id}/turns query=TurnsQuery resp=TurnsPage`). `go generate ./internal/web` appends new lines and never removes one, and a test fails when a committed line is missing from or changed in the regenerated set. Removing a field or a route means deleting its line by hand in the same commit, which a review sees. This replaces the Convention "never rename or retype a field".
20. **One request path in the app:** every generated function calls `request()`, which turns statuses into typed outcomes: 401 unpaired (the cached snapshot is cleared and the app shows pairing), 409 the model's refusal with its text, 503 the daemon stopping, 504 timed out, 202 pending (the outcome arrives on the stream), any other failure an error with the answer's `error`; and every response's `notices` become toasts, Kill's and Resume's stash notices always shown.
21. **Not a generic bridge to Core methods:** the web faces the internet and its JSON outlives a build, so each route stays a deliberate projection. `internal/web/README.md` keeps its prose (how the layer runs, pairing, the stream, push, limits); its route table moves to `docs/specs/web-api.md`.

### The client

22. **Panels:** each view is a panel registered with `definePanel` (id, route, title, icon, which sessions it applies to, whether it is a session tab and in what order, `Head`, `Body`), in `src/panels/<id>/`. The phone layout draws one panel per route and builds the session tabs from the tab panels that apply to the session: info always, the conversation for a session that runs Claude, changes and mockup under the classic conditions (`SessionTabs`). Desktop composes several from the same registry. This replaces `screens.mjs`.
23. **Commands:** every action is a command registered with `defineCommand` (id, title, icon, `when`, an optional confirmation sheet built from the context, `run`). `when` reads only the session's status, its `claude` flag, the route and the link state, never a copy of the model's preconditions: the model decides, and a wrong guess is its 409. Buttons render from commands (`CommandButton`), so label, enablement, confirmation and toasts are uniform. Commands: a session's send, answer, pause, resume, kill, push, merge and Open in Claude; a job's start, park, unpark, pause and resume; new session; push enable; quick-reply save; device notification settings; unpair; the switch. Every command is off while the snapshot is stale.
24. **The live store** (Zustand, `src/store/`): it holds the snapshot and applies each stream event; components read it through selectors (`useSession(id)`, `useFleetGroups()`, `useLink()`), so an event re-renders only what read the changed data. It saves the snapshot to IndexedDB `loom-next` at most once a second with the time last heard from the daemon; a cold start draws it at once, marked stale, until the stream's first snapshot. A 401 or an unpairing clears it. The badge is set from each event's `badge` as today.
25. **The stream** (`src/api/stream.ts`) keeps the classic rules: reconnect with a backoff from 1 s to 30 s, drop a stream silent for 45 s, open a fresh one whenever the page becomes visible, and show the link state (LIVE, CONNECTING, RESTARTING after a `bye`, OFFLINE) in the footer.
26. **Reads** go through TanStack Query: turns (paged back by `before`, the newest refreshed by `after`), the diff, a flow, a flow document, the host's flows, a job's log and launch defaults. Each panel keeps the classic screen's refresh rules (`internal/web/README.md`, The app) as query options, among them: the conversation refreshes its newest turns when the stream changes the session's status or last message and every 5 s while it is Running; the changes panel when its counts or status change and every 10 s while Running; a job's log every 2 s while the job has yet to end and the page is visible, and once more when it ends; the subagent panel every 5 s while its agent runs, or its state is unknown and the session is Running, and once more when it finishes. The query cache and a store slice for reply drafts replace the classic module-level maps with their limits: turns and scroll position for the last 8 sessions, logs for the last 5 jobs at most 512 KiB each, and a reply draft per session that survives tab switches.
27. **Routing** (TanStack Router, hash history): every classic URL resolves to the same view, `#s/<id>/turns` replaced by `#s/<id>` in place, and push links (`/#s/<id>`, `/#s/<id>/mockup`) open as today. Route params and search (`?plan=`, `?at=`) are typed. The app writes its own links as `#/s/<id>`, and rewrites a hash without the leading slash (`#s/<id>`, as pushes and the classic app's links have it) in place before it routes, so both forms open the same view.
28. **The worker** (`ui/public/sw.js`) keeps the classic worker's behaviour: it caches the shell only and never `/api/`, installs when the app asks it to update because a snapshot's `build` differs from the shell's (once per build, as `upgradeShell` does), shows every push as a notification tagged by session with the classic payload (`kind`, `session`, `title`, `body`, `badge`, `url`), sets the badge, and opens the push's `url` on a tap.
29. **Failure containment:** each panel renders inside an error boundary that shows what failed and a reload, so one broken view never blanks the app. A value the app's union does not know, from a newer daemon, falls back as the classic app does (an unknown group lists under Paused) and is never dropped; an unknown status or state shows its raw text in neutral styling.

### The design system

30. **Tokens** in Tailwind 4's `@theme`: shadcn's names (`--background`, `--foreground`, `--card`, `--popover`, `--primary`, `--secondary`, `--muted`, `--accent`, `--destructive`, `--border`, `--input`, `--ring`) plus loom's semantic tokens: `--attention` (needs you, amber), `--turn` (your turn, blue), `--working` (green), `--error`, `--workspace` (pink), `--docs` (purple), `--diff-add` and `--diff-del`. Dark values as the mockup (`docs/superpowers/specs/2026-11-18-web-foundation/design-system.html`): background `#0f1012`, card `#16181c`, border `#23262b`, foreground `#e6e7ea`, muted `#a3a8b1`, attention `#f0b45a`, turn `#6ca4e0`, working `#8fc46a`, error `#e8836b`, workspace `#d9a3b8`, docs `#a991d4`. A light set is a later second block of the same names.
31. **Type:** Inter for the UI and JetBrains Mono for code, commands, branches, paths, diffstats, job logs and ids, both variable fonts, latin subset, bundled from npm (`@fontsource-variable/inter`, `@fontsource-variable/jetbrains-mono`) and served by the daemon (the CSP allows no font CDN), with system fallbacks in each stack. Tabular figures are on wherever numbers line up (ages, costs, shares, diffstats).
32. **Components** are shadcn's, initialised on Base UI and kept as owned source in `src/components/ui/`: Button, Badge (pills), Tabs (session tabs), Toggle Group (the workspace filter), Drawer (bottom sheets: confirmations, the ask forms on the phone), Dialog, Toast (toasts), Collapsible (thinking, step folds, Paused), Select (new-session options), Switch (settings), Textarea (reply), Skeleton (loading), Input OTP (the pairing code), with lucide icons. The Drawer and the Toast are built on Base UI's own Drawer and Toast, not on vaul and Sonner (owner, 2026-11-18): sonner 2.0.8 and vaul 1.1.2 each append a `<style>` element when they load, which §33's CSP blocks, while Base UI's inject nothing, and vaul would pull Radix's Dialog into a Base UI app.
33. **The CSP stays `default-src 'self'`.** A library that injects a `<style>` element at runtime has its CSS imported statically or is replaced; webshot runs under the real CSP, so a violation fails CI. No module writes a `style` attribute as markup or sets HTML from a string; Claude's text is drawn from its tree (`buildTree`) as elements and text nodes, as today.
34. **Phone rules carried over:** form text at 16px (iOS zooms a smaller one), safe-area insets (`env(safe-area-inset-*)`, `viewport-fit=cover`), touch targets of at least 44px, `prefers-reduced-motion` respected, the footer hidden while the reply box has focus.

### Docs and rules

35. **A new `internal/web/ui/CLAUDE.md`** holds the app's rules: never edit `dist/` or `src/api/gen.ts` (regenerate with `pnpm build` and `go generate ./internal/web`; **Enforced** by `web.yml`'s freshness step and the generator's test); add a view only as a panel and an action only as a command; a command's `when` reads only status, the `claude` flag, the route and the link; no runtime `<style>`, no markup `style` attribute, no HTML from a string; 16px form text; the classic tree is frozen until cutover. `internal/web/CLAUDE.md` replaces its route-checklist Convention with the route table's enforced rules (§16, §19) and stays within its budget. Root `CLAUDE.md` does not change: 108 bytes of headroom, and the rules load from the web files where an agent edits.
36. **`docs/claude/web-layer.md`** gains the procedures: add a panel, add a command, add a route (table entry, typed handler, regenerate, `api.fields`), add a stream event, the dev loop (`pnpm dev` against `webshot -serve`), and reading the budget test's failure. The build writes every bundled package's and font's licence into `dist/THIRD_PARTY.txt`, and `NOTICE.md` points there.

## Errors and edge cases

- **A switch while offline:** the cookie is set, the worker's update fails, and a toast says the switch happens on the next launch (§4).
- **An installed app older than the daemon:** the classic case, unchanged: fields only grow (§19), and the worker updates on the next snapshot whose `build` differs.
- **A stray request for the other tree's asset** just after a switch is answered from that tree (§3).
- **IndexedDB unavailable** (a private window): no cold-start snapshot; the app works live.
- **A font that fails to load** falls back to the system stack (§31).
- **A panel that throws** shows its error boundary; the header, footer and other panels keep working (§29).
- **A bundle over budget** fails the Go test with the measured size and the files counted (§15).
- **A daemon refusal** is the model's 409 text in a toast; a stopping daemon's 503 shows RESTARTING until the stream returns (§20, §25).

## Testing

- **Vitest** (happy-dom, Testing Library): the store applying each stream event (snapshot, sessions, workspaces, usage, quick_replies, device, notice, bye); grouping, ordering and the status row's cycling (`groupSessions`, `fleetGroups`, `nextInGroup` semantics); every classic URL resolving to its panel, `#s/<id>/turns` included; `request()`'s mapping of each status; each command's `when` across statuses and link states; the unknown-value fallbacks; the ask forms (a question's options, Other, a note, Chat about this; a permission's Allow, suggested rules, Deny with a message); reply drafts across tab switches; each confirmation sheet naming what it does (the worktree path and tmux session for Kill); Claude's text rendered from a tree as elements and text nodes, never an HTML string.
- **Typed fixtures:** Vitest and webshot read the same `tools/webshot/fixture/*.json`; a test asserts each `satisfies` its generated type, so a Go change that breaks a fixture fails the typecheck.
- **webshot in CI** renders every route of the new app under the real CSP (§14).
- **Go:** both static trees served through `buildStaticAssets` (placeholders, precache lists, content types, no inline script in either `index.html`); the cookie switch (`next` serves the new shell, anything else the classic one, `Vary: Cookie`, asset fallback across trees); the route table's open set; the generator's freshness; `api.fields` only growing; the bundle budget. `e2e/web_test.go` runs unchanged: the API does not change.
- **The iPhone checklist** (§9): switch the installed classic app to the new one in place; pair a fresh install; receive a waiting and a finished push with the app open and closed; Open in Claude; reply, and run a slash command; answer a question and a permission; kill with its confirmation and see the stash notice; revoke the device; switch back to classic.

## Delivery

An epic of 3 parts, each a plan merged to main before the next part is designed.

1. **Part 1: the contract and the shell.** The route table and typed handlers (§16–§17); the generator, `gen.ts`, `web-api.md` and `api.fields` (§18–§19); the `ui/` toolchain, the dev shell, the committed `dist/` and the embed (§10–§11, §13); the cookie switch, the classic Settings row, the new app's command on every placeholder, and the cache cleanup (§3–§6); tokens and fonts (§30–§31); `request()`, the stream, the store, the query setup and routing (§20, §24–§27); the panel and command registries (§22–§23); the shell (header, footer status row, toasts, sheets, error boundaries, link states, the worker with push, the badge and the launch-time subscription check, §28–§29); the placeholder for unported routes (§7); the fleet panel; webshot's `-app` and `-serve` (§12); `web.yml` and the budget test (§14–§15); the rules and procedures (§35–§36). It ends with the fleet usable in the new app behind the switch.
2. **Part 2: the session views.** The conversation (turns, thinking, agent links, fact strip, needs-you box, asks, reply box with quick replies and slash commands), info (tiles, agents, jobs, actions and their sheets), changes, the subagent view, the job view, and the mockup views.
3. **Part 3: the rest, to parity.** The flow board, row and document views; the host's flows; new session; settings (notification toggles, enabling push, quick replies, unpair, the switch); pairing and Add to Home; the iPhone checklist. It ends with no route drawing the placeholder.
