# watch

The issue watcher's logic: the `loom-watch.json` config, the title template and the branch pattern derived from it, and prompt rendering. It holds no model state: `core` imports it and calls it from the loop and from a poll job, so it imports nothing from `core`. Facts in [`README.md`](README.md).

## Rules when modifying this package

- **Keep `maxTitleWidth` equal to `core.MaxTitleWidth` (32 cells).** `watch` can't import `core` (core imports it), and a title wider than core accepts is refused at the start of every session, so the issue never gets one and the status says only that the start failed. **Enforced** by `TestMaxTitleWidth_MatchesCore`.
- **Derive the branch pattern from `git.SanitizeBranchName` itself (`TitleTemplate.BranchPattern`), never from a copy of its rules.** The watcher recognises its own PRs by that pattern, and one that drifts from the sanitizer stops matching them: their issues get a second session and the PRs are never nudged or settled. **Enforced** by `TestTitleTemplate_RoundTrip`.
- **Refuse a title template whose literal beside `{issue}` is empty after `git.SanitizeBranchName` or touches the number with a digit (`ParseTitleTemplate`), and a title variable value with no letter or digit (`Render`), and test the branch pattern against issues that extend the number (`N*10+d`, `d*10^k+N`), not only `N+1`.** The sanitizer drops characters such as `#` and `:`, so with `heal {issue}#{spec}` issue 56's branch matches issue 5's anchored pattern and a value of only `-` or `.` merges into the separators: the watcher then nudges, settles or kills the wrong issue's session, or fails to recognise its own branch, with no error. **Enforced** by `TestParseTitleTemplate_Invalid`, `TestTitleTemplate_RoundTrip` and `TestTitleTemplate_Render`.
- **Treat any fault in `loom-watch.json` as the whole file's (`ParseConfig`): an unknown key, a missing required key, a value outside its bound, a version other than 1 return an error naming the key and a zero `Config`, never a default for the bad value.** A silently defaulted value runs the watcher on settings nobody wrote, starting and killing sessions on them. **Enforced** by `TestParseConfig_Invalid`, `TestParseConfig_Required` and `TestParseConfig_Bounds`.
- **Render a prompt's variables in one pass and refuse an unknown name (`RenderPrompt`).** Values such as the issue's title come from GitHub, so a second pass would let an issue's text decide what the prompt says by naming a variable, and a name left unreplaced would reach the agent as a literal `{name}`. **Enforced** by `TestRenderPrompt_SinglePass` and `TestRenderPrompt_UnknownNameIsAnError`.
- **Refuse an unreadable, undecodable, version-less or newer `watch.json` (`LoadMemory` returns an error) and never write over it.** Acting without the nudge counts and escalations re-nudges every PR and re-escalates every issue, and the file may hold what a newer loom recorded; the watcher stops for that workspace and says why. **Enforced** for the refusal by `TestLoadMemory_RefusesAndKeepsTheFile` and `TestLoadMemory_NewerVersionIsRefusedBeforeItsShapeIsRead`, and for the stopped watcher leaving the file alone by core's `TestWatchPoll_TheMemoryIsLoadedOnceAndABadFileStopsTheWatcher` and `TestDeliverWatch_ABadMemoryFileKeepsTheWatcherStopped`.
- **Build the hook's child by `hookEnv` and run it through `runHook` with `cmd.WaitDelay` set: `PWD` is set to the hook's directory, the two `LOOM_WATCH_*` variables go last, and a killed hook's descendants are cut off after `hookWaitDelay`; keep the last stderr line a whole-rune, plain-text cap (`hookLastLine`).** `os/exec` updates `PWD` only when `Env` is nil, so a hook reading `$PWD` sees the daemon's directory; a child of a timed-out hook (a `sleep` run by the script, not exec'd) holds the pipes open, so without `WaitDelay` the call waits out the child and stalls the watcher's poll; and a cut inside a multi-byte rune puts invalid UTF-8 into the status. A test passes anyway through a directory with no symlink (`sh` recomputes a stale `PWD` itself), a hook that execs its sleep, or a cap case that lands on a rune boundary. **Enforced** by `TestRunHook_ChildEnvironment` (the hook's directory is reached through a symlink), `TestRunHook_TimeoutWithSurvivingChild` and `TestHookError_StderrLineIsCappedAndPlain`.
