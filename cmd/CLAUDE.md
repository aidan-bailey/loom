# cmd

The `loom workspace` Cobra subcommands (`WorkspaceCmd`: add, list, remove, use, rename and status in `workspace.go`, migrate in `workspace_migrate.go`), `loom account` (`AccountCmd`, `account.go`), and the subprocess seam: `cmd.Executor` re-exports `internal/exec.Executor` for testability, and the production implementation, `internal/exec.Default`, is aliased as `cmd.Exec` and returned by `MakeExecutor`; tests use `MockCmdExec` (`cmd/cmd_test/testutils.go`).

## Rules when modifying this package

- **Never import `session` from non-test code; ask `session/agent`'s adapter registry instead** (`isClaudeProgram`, not `session.IsClaudeProgram`). `session/tmux/tmux_test.go` imports `cmd`, so `cmd` importing `session` (which imports `session/tmux`) cycles in that test build. **Enforced** by the compiler: `go test ./session/tmux` fails with "import cycle not allowed in test".
- **Changing `session.InstanceData`?** `workspace migrate` decodes records into its own typed mirror (`migrationInstance`) and writes them back through `config.SaveStateTo`, so a field the mirror lacks is silently dropped from every record it moves; update the mirror and the fixture in `cmd/workspace_migrate_shape_test.go`. **Enforced** by `TestMigrationInstance_TypeDriftGuard` and `TestMigrationInstance_MirrorsInstanceData_JSON`.
- **Run `StateWriteGuard` before any command that writes `state.json` itself.** `main.go` sets it to `refuseWhileServed`, so `workspace migrate` refuses while the daemon runs, which would otherwise overwrite the migration with its own save. **Enforced** by `TestStateWriters_RefuseWhileTheDaemonRuns` (`main_test.go`).
- **Let `remove --force` alone override the in-use and unshared-files refusals, report what it overrode, and still confirm.** `--yes`/`-y` skips only the prompt, so deleting a session's only account is never one accidental keystroke away. The unshared-files check runs, and reports, before the prompt, and the prompt says "delete `<dir>`" only when `Registry.OwnedDir` says loom owns the dir, else that the dir is left in place. **Enforced** for the flags, the refusals and their order by `TestAccountRemove_…` (`cmd/account_test.go`); **Convention** for the prompt's wording — a user told a dir will be deleted that is left, or the reverse.
- **Validate the main dir before `add` or `sync` links anything** (`account.ValidateMainDir`), and refuse `add`/`sync` when no main config dir can be found. **Enforced** for an unknown main dir by `TestAccountAdd_RefusesWhenMainDirIsUnknown` and `TestAccountSync_RefusesWhenMainDirIsUnknown`; **Convention** for an unsafe one, which only `ValidateMainDir`'s own tests (`account/link_test.go`) cover — links made from inside the accounts dir.
- **Refuse `add`, `list`, `sync` and `login default` when the shell's own `CLAUDE_CONFIG_DIR` resolves inside `<AccountsDir>/<name>`** (`guardAgainstAccountEnv`, `accountFromEnv`): from an account's agent pane, treating the inherited env as the default account logs the wrong identity in as default or lists and syncs it as the main login. `use`, `remove` and `login <account>` for a named account read that account's own override and still work. **Enforced** by `TestAccountCmds_RefuseWhenRunningAsAnAccount` and `TestAccountCmds_NamedAccountOpsStillWorkUnderAccountEnv`.
- **Refuse `login` for a registered account whose dir is missing.** `claude auth login` would recreate it bare, unlinked and logged out; the message says to `remove` the account and `add` it again. **Enforced** by `TestAccountLogin_RefusesWhenTheAccountDirIsMissing`.
- **Wrap the login child in `signal.Notify`/`signal.Stop`, never `signal.Ignore`** (`runWithChildSignals`). An ignored SIGINT is `SIG_IGN` at the OS level and survives `exec`, so Ctrl-C during `claude auth login` would reach neither loom nor claude (verified against a real child's `/proc/self/status` `SigIgn` mask); `Notify` resets to the default disposition across `exec`. **Enforced** by `TestRunWithChildSignals_DoesNotLeakSignalIgnoreIntoTheChild`.
- **Probe `list`'s accounts in parallel, and skip the default account's probe when no main config dir is known.** `ProbeUsage`'s working directory becomes a project entry in Claude's own config, so it never runs wherever `list` was invoked; the row says "no main config dir found". **Enforced** for the skip and the row order by `TestAccountList_SkipsDefaultProbeWhenMainDirIsUnknown` and `TestAccountList_OrdersRowsByNamesRegardlessOfProbeTiming`; **Convention** for the parallelism, which the instant fake executor can't show — a `list` that waits on each probe in turn.
- **Read the Claude binary from the global dir's `config.json`** (`claudeProgram()`, through `config.GetGlobalConfigDir()`), matching the TUI's global context (`config.GlobalWorkspaceContext()`) rather than `LOOM_HOME`'s, since one account registry serves every workspace. **Enforced** by `TestClaudeProgram_PrefersTheGlobalConfigDirOverLoomHome`.
- **Warn about a credential override in `add`, `login` and `list`, from the CLI's own environment** (`warnCredentialOverride`). With one set every account bills as it; `use` and `sync` run no session and stay quiet. **Enforced** by `TestAccountList_WarnsWhenACredentialOverrideIsSet`, `TestAccountAdd_WarnsWhenACredentialOverrideIsSet` and `TestAccountLogin_WarnsWhenACredentialOverrideIsSet`.
