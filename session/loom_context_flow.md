## The agent flow

Loom ships the agent flow as the `flow` plugin: the skills `/flow:init`, `/flow:draft`, `/flow:supervise`, `/flow:run` and `/flow:retro`, and its pinned agents, dispatched as `flow:<name>` (`flow:verifier`, `flow:intermediate-dev`, …). In a repo where `loom flow conf status` names a profile and whose own CLAUDE.md defines no supervised option, `superpowers:writing-plans` asks for the execution option before it writes the plan, and adds a third: **3. Supervised**, "a skeleton now; `/clear`, then `/flow:draft <plan>`; `/clear`, then `/flow:supervise <plan>`: drafters write the stories, then a supervisor runs them story by story with the pinned roster, and escalates what the spec doesn't settle." For option 3 the design session moves every decision into the spec, writes only the skeleton, in the format of the skeleton section of flow's dispatch guide, and commits both by pathspec; it drafts nothing. A plan is drafted from its spec, never generated from a prototype of the code. `/flow:supervise` also runs a plan written by hand that `loom flow check-plan` passes. `/flow:init`, `/flow:draft`, `/flow:supervise`, `/flow:run` and `/flow:retro` are the owner's to type: asked to run one, say so, and never read its SKILL.md to follow it yourself. Flow's guides are files in this session's copy of the plugin: `loom flow path docs/dispatch.md` prints the dispatch guide's path.
