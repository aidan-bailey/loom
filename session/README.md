# session

The core domain: `Instance`, a running agent session in its own git worktree and tmux session, with its storage, reconcile, orphan discovery, resume decisions, Claude status, hooks, temp-dir archiving and launch environment. The model in [`../core/`](../core/README.md) drives it; the TUI never holds an `Instance`. `session/` itself holds the instance and everything that acts on it; the sub-packages (`session/agent/`, `session/claudetmp/`, `session/files/`, `session/github/`, `session/hooks/`, `session/launch/`, `session/subagent/`, `session/git/`, `session/vt/`) are described at the end, and `session/tmux/` has its own [`README.md`](tmux/README.md).

## Instance

`Instance` (`instance.go`) has a status lifecycle: `Ready` (initial), `Loading` (setup in progress), `Running` (agent active), `Paused` (worktree removed, branch preserved), and `Recoverable` (an orphaned worktree found on disk, surfaced inline for recover or discard; never persisted). Its own API is lifecycle and state.

Its tmux session is a lifecycle-only `tmux.Session` that never attaches a client: the TUI's pane clients do that. Whatever lifecycle does to the agent's pane without a client lives on the `AgentPane` value `Instance.Pane()` returns (`agent_pane.go`): liveness probes, the session name and the program the session was launched with (`SessionProgram`), typing text and prompts (`SendKeys`, `SendPrompt`: `load-buffer` + `paste-buffer`), pressing Enter (`TapEnter`: `send-keys`), and a capture-pane `Preview`; for example, `inst.Pane().SendPrompt(…)`. Rendering the pane and forwarding input through a PTY go through the TUI's attach clients (`ui.Pane`, from `ui.PaneClients`), keyed by session name, whose adapter comes from `inst.Pane().SessionProgram()`, never `Program`: a resume that reattaches a live session (`R` with a new program) keeps the old `tmux.Session`, while `Program` already names the new one. `Instance.Kill` and `Pause` end the agent's session and the terminal pane's `loom_term_` shell by name (`CloseRelatedSession`), which gives each attach client's pump EOF; neither closes a client itself. A `session.Instance` never reaches the TUI.

Launch fields are set through `SetLaunchOptions`/`SetProgram`/`SetPrompt`/`SetCrashRecovered` and read through `Program()`/`HeadroomProxy()`/`CacheTTL1h()`/`Prompt()`/`CrashRecovered()`, never assigned directly: the accessors lock `i.mu`, so `session` code that already holds it reads the private fields instead (the lock is not reentrant).

`FromInstanceData` is a pure constructor: it spawns no tmux session. `inst.EnsureRunning()` only marks a restored instance whose session runs as started. Nothing in `session` attaches a PTY.

## Storage and schema

`storage.go` (`session.Storage`, which carries its own mutex) serializes the `instances` array in `state.json` (not a separate file; `config.InstancesFileName` is unused). Since schema v6 a record's `issue` links a session to the GitHub issue it was created from; since v7 `claude_session_id`/`claude_transcript_path` name the conversation a crash relaunch resumes with `--resume`; since v8 `account` names the Claude account it runs on (empty means default).

`session.InstanceData` has a `SchemaVersion` field and `session.CurrentSchemaVersion` constant; `session/storage_migrate.go:Migrate` upgrades a record step by step, and `MigrateAll` runs it over a payload. A record `Migrate` rejects, or one that fails to decode (corrupt, or a `schema_version` newer than this binary after a downgrade), is skipped, held as raw bytes (`UndecodableCount`), and appended verbatim to every write. `SaveInstances`, `DeleteInstance` and `UpdateInstance` all go through `writeLocked`, which also loads first on a never-loaded `Storage`. Records that fail `ReconcileAndRestore` are kept as raw `InstanceData` (the unrecovered cache), so a transient failure does not drop them at the next save.

A payload that is not a JSON array fails the load and latches every write shut (`ErrStorageLoadFailed`, state untouched) until a later load succeeds; `WritesRefused()` reports it. `DeleteAllInstances` (`loom reset`) is the one write allowed through, and clears the latch. Both kinds of preserved record are claimed by worktree path (`PreservedWorktreePaths`), so orphan discovery doesn't offer them as `Recoverable`, and by title (`PreservedTitles`, folded in by core's `claimTitles` at every sweep site), so the orphan tmux sweep and the hooks sweep spare their sessions, workspace-terminal auto-create doesn't kill and duplicate a preserved terminal, and a new session can't take a preserved title (the TUI's `preservedTitleErr`); both are counted in the recovery summary.

`loom workspace migrate` (`cmd/workspace_migrate.go`) bypasses `writeLocked`: it decodes records into its own typed mirror and writes via `config.SaveStateTo`, so a newer-schema record passing through it loses every field this binary doesn't know. Changing a field: [`../docs/claude/changing-the-instance-schema.md`](../docs/claude/changing-the-instance-schema.md).

## Reconcile, orphans and ownership

`Storage.LoadAndReconcile` restores each record against tmux and disk. `tmux.RenameLegacySessions` runs there, before per-record reconcile, on every load path, so live `claudesquad_` sessions are renamed `loom_` and keep their panes.

`orphan.go` (`session/orphan.go`) discovers worktree directories on disk that `state.json` doesn't reference (`DiscoverOrphans`) and classifies them (`Disposition`): stale leftovers (dead tmux, clean tree) are auto-cleaned (`RemoveOrphanWorktree`), and ones with unsaved work or a live agent surface inline as `Recoverable` entries. A live orphan keeps its account: discovery reads the session's `CLAUDE_CONFIG_DIR` back with `tmux show-environment` and maps it through the registry (`liveSessionAccount`). A dead one recovered from disk (`r` on a `Recoverable` entry) comes back on the default account, since nothing on disk records which account it ran on.

tmux names are per server, not per workspace, so `reconcile.go` proves ownership before it acts. Each check takes the record's `session.SessionHome{Dir, Exact}` (`Instance.SessionHome`): an agent's session starts in its worktree, so one started there or below is its own; a workspace terminal's starts in its repository itself (loom launches it with `-c <repo>`), so only an exact match is, because an agent titled after the workspace starts its session in `<repo>/.loom/worktrees` under the terminal's tmux name.
- **`startedElsewhere`** counts only positive evidence: a non-Paused record whose name is alive on a session started anywhere else goes straight to `ActionMarkPaused`, workspace terminals included, so reconcile neither restores it onto that session, crash-restarts it under a name known to be taken, nor kills the other session. An unreadable listing or start directory keeps the old behaviour, which may restore onto or kill that session; `HeldElsewhere` is the fail-closed check.
- **`HeldElsewhere`** is asked by a caller about to kill or replace whatever runs under a name, and fails closed with three outcomes: held (a live session not provably the record's own, one with no start directory included), free (no session of that name, or no server), or an error (a listing tmux left unanswered, a timeout under load: change nothing and ask again). `Instance.Kill` and `Instance.Resume` ask it of the session under the record's name (`sessionHeldElsewhere`, through `tmux.Session.StartDir`): a kill leaves a held name's sessions running, the agent's and the terminal-pane `loom_term_` shell, and cleans up only what is the record's own; a resume refuses on a held name before `decideResume`; both refuse, changing nothing, when tmux can't say whose the session is.
- **The orphan tmux sweep** (`CleanupOrphanedSessions`) sees every session on the server, and "not in my lists" is no proof of an orphan. It reads each session's start directory (`#{session_path}`, the `-c` dir loom passes to `new-session`; unlike `pane_current_path` it ignores a later `cd` and survives the dir's deletion) and kills an unclaimed `loom_*`/`claudesquad_*` session only when that directory, compared after `filepath.EvalSymlinks` and component-wise (`/a/repo` does not hold `/a/repo2`), lies inside an owned root of its `SweepScope` (`session/reconcile.go`), with no foreign root nested deeper. Owned roots are each served workspace's repo root and `<configDir>/worktrees`, except a workspace whose load failed (`WorkspaceSweepRoots`; `NewSweepScope` builds the scope from the same workspaces `claimTitles` covers, in core's `sweepOrphans` at boot and in `loom reset`); foreign roots are every other registered workspace's, a failed one's included, and the global worktrees dir. An empty, relative or unplaceable directory is left alone (`orphan_tmux.skip_unowned`, debug), as is a name that cannot be targeted exactly (`tmux.ExactlyTargetable`, `orphan_tmux.skip_untargetable`). Kills are exact-name (`-t=`, through `tmux.SessionTarget`). The sweep returns a `SweepResult` (killed, unowned, untargetable, failed; logged as `orphan_tmux.sweep_done`) and an error for any listing failure other than "no server running" (`isNoTmuxServer`) and for every failed kill, so `reset` stops before deleting worktrees and branches under live agents (`TestResetCmd_StopsBeforeWorktreesWhenSweepFails`); the boot's sweep only logs it. `loom reset` kills only the reset workspace's sessions (default: global's).
- **`KillOwnedTmuxSession`** applies the sweep's test to one title: a workspace terminal's title is just the workspace's name, which another loom's workspace can share, so a session not started in this workspace's roots, or any listing that fails, is left running.

Two global dirs that register the same repository both own its roots, so each one's boot could sweep the other's sessions there (rare; unguarded). The sweep does not stop a nested dev daemon serving the same workspaces as its host from sweeping the host's sessions; the nesting guard in the root's `serve.go` does.

## Resume, worktrees and failed starts

When an agent exits on its own (`/exit`, a crash), the model's tick only calls `TransitionTo(Paused)`: no stash, no removal, so the worktree still holds the only copy of any uncommitted work. The same state arrives via a failed `CrashRestart` and via adopting a dead-tmux `Recoverable` orphan (adoption sets `crashRecovered`, but nothing restarts it, so the tick pauses it).

Resume classifies the path with `GitWorktree.InspectTree` and feeds it to the pure `decideResume` (`resume_decision.go`): a live session is reattached; dead + intact relaunches in place with the agent's recovery flag (recording a missing base commit, `EnsureBaseCommit`); dead + gutted rebuilds (leftovers moved aside); `TreeUnverified` or an unanswered probe refuses. The unverified refusal (`unverifiedTreeError`) tells a `git.IsTimeout` (retry) from a rejection (move the directory aside, with a shell-quoted `mv`; the next resume rebuilds), and `sameFile` reports a path it cannot stat as that error, never as the tree belonging to another repository. `finishResume` closes the dead session object before starting its replacement and refuses when the probe gets no answer.

Anything that reaches `gw.Setup()` runs `git worktree remove -f`, which silently deletes an intact dirty tree. `CrashRestart` refuses a non-intact tree for the same reason, `startFreshWithRecovery` never cleans up on a failed start (its old `gw.Cleanup()` deleted the tree and the branch), and `Start(true)`'s failed-start cleanup (`failedStartCleanup` → `CleanupFailedStart`) deletes the branch only if `Setup` created it (a reused title checks out the branch an earlier session left behind). That cleanup runs only when nothing can be running in the tree: a name `tmux.Start` refused before launching (`tmux.ErrSessionExists`), or a session `SessionLiveness` confirms Dead, as Pause requires. Any other failure may come after the agent launched, so the tree and branch stay and the error says the agent may still be running.

## Stashes and notices

A pending `StashRef` in place (`restoreStashInPlace`):
- no longer in `git stash list`: forget it, never re-apply it, whatever the tree holds;
- clean tree: apply;
- tree already equals the stash (`StashOnDisk`, an interrupted pause): forget it and drop the duplicate;
- dirty and different: refuse, naming the full SHA, until the user drops the entry.

The rebuild path asks `StashListed` too, before `Setup`, and fails closed (nothing rebuilt) when the list can't be read. When Pause aborts because the session survived `Close`, it drops its own stash and saves the cleared reference: the tree still holds everything the stash captured.

`ApplyStash` returns `git.ErrStashNotDropped` when the apply worked but the drop didn't (callers clear the reference and pass it on). A Resume or Kill that succeeded with something to report returns a `session.Notice` (`notice.go`; `OnlyNotice` means the operation succeeded, `NoticeIn` finds one inside a failure), naming the SHA: a forgotten stash's Resume notice adds `git stash apply <sha>` / `git fsck --unreachable | grep commit`, while Kill's undroppable-stash notice names the SHA only. The model reports them as `core.Notice` events (`resumeOutcome` → `ResumeResult.Notice`, `KillResult.Notice`), which the TUI shows through `handleError`; a Lua `inst:resume()`/`inst:kill()` returns without raising and its `Reply` carries the notice. Pause's abort includes a failed drop in its error. Tests: `session/resume_inplace_test.go`, `session/resume_decision_test.go`, `session/start_cleanup_test.go`, `session/stash_notice_test.go`.

## Claude status

Each Claude instance holds one merged observation (`claude_state.go`, `claudeState`, guarded by `Instance.mu`). Hook events (`SessionStart`, `UserPromptSubmit`, `PermissionRequest`, `Notification`, `Stop`, `SessionEnd`) and roster answers are both offered to it, each stamped with when it was observed (a hook event's `At` from its file name, `hooks.eventTime`; a roster answer's query start), and the newer one wins whichever source it came from. There is no grace window: a live probe (spec `docs/superpowers/specs/2026-09-23-claude-hook-events-design.md`, payloads in `session/hooks/testdata/probe-2.1.280/`) showed the roster moving slightly before the hook's timestamp, so an answer stamped after an event already reflects it, and stamping with the query's start is conservative. `TestRealClaude_HookStatusContract` (opt-in) asserts that ordering.

Rules of the merge: only parent events (no `agent_id`) count, except `PermissionRequest`, whose prompt shows in the parent; `Stop` ends a turn, not the work (a `Stop` listing a running `subagent` task is Running, and teammate and `shell` tasks never count, since idle teammates stay listed as running); only `SessionStart` sets the session ID (a failed `--resume` sends a `SessionEnd` carrying the unknown ID); a roster answer with no opinion voids a roster-sourced status but never a hook-sourced one; a same-status roster answer keeps the hook's more specific reason (`permission: Bash`). A reported status also exempts the session from the TUI's Ready→Running promotion on output (`paneDirtyMsg`).

Without a working roster two gaps remain: an answered prompt stays Prompting until the next hook, and a lead resuming after a teammate reply shows Ready. A relaunch resumes the recorded conversation (`BuildResumeCommand`, `agent_restart.go`: `--resume <id>` when the ID is a UUID and its transcript exists, else `--continue`; Claude writes the transcript with the first message, so a session that never got one falls back), and a stopped session's card shows the end of Claude's last message (`ui.MessageTailLines`), valid from its `Stop` until the next prompt or permission request. App and core test instances start on a mock tmux session, so `Start` never prepares their hooks folder: like a restored instance they have no launch ID and adopt a scan's. Tests: `session/claude_state_test.go` (a replay of the whole probe included), `core/claude_status_test.go`, `core/hook_scan_test.go`, `app/claude_status_test.go`, `ui/card_message_test.go`, and in `e2e` `TestE2E_FakeClaudeHooksDriveStatus`.

**The roster** (`claude_roster.go`): `QueryClaudeRoster`/`QueryClaudeRosterEnv` run `claude agents --json` (through `account.Command` for an account's config dir) and key every live Claude session by cwd. Only interactive entries are joined: background (`claude --bg`) sessions publish `state` where interactive ones publish `status`, and a `--bg` session started inside a worktree would otherwise collide with loom's own session. An entry with no `kind` counts as interactive (older CLI builds omit it). Two interactive sessions in one directory are an ambiguous cwd, dropped with a `session.roster.ambiguous_cwd` debug line. The CLI is never a hard dependency. Tests: `session/claude_roster_test.go`.

## Hooks and subagents

Transcripts can't say whether an agent is running (each content block is its own record, and the stop reason is missing from most responses), so Claude is launched with `--settings {ConfigDir}/hooks/<folder>/settings.json`, where `<folder>` is the path-escaped tmux session name (`hooksFolderName`: `url.PathEscape(tmux.ToLoomTmuxName(title))`, always one path segment, so a `/` in a title can't nest one instance's folder inside another's, where launching, killing or sweeping the outer one would delete it). It registers `SubagentStart`/`SubagentStop`/`TeammateIdle`/`Stop`/`SessionEnd` plus the status events. Each hook writes a file to `events/`; core's `maybeHookScan` (`core/hook_scan.go`) collects them into `Instance`'s `subagent.Tracker` and `claudeState` (`session/subagent_hooks.go`, `session/hook_scan.go`).

Hooks are prepared only on real launches (`launchProgram(…, true)`: `Start(true)`, `startFreshWithRecovery`, `CrashRestart`, `Restart`), never on `Restore`, because a reattached Claude is still writing to its folder. `Restart()` (the workspace-terminal auto-restart) closes the dead session and rebuilds it as `Session.WithProgramEnv(launchProgram(program, true), env)` with a freshly resolved env. Every real launch first resets the previous launch's state, even when hooks end up skipped: `resetHookLaunch` clears the tracker, warm flag, Claude status and last message (keeping the conversation ID the relaunch resumes), sets the launch ID to the `noHooksLaunchID` sentinel so no scan result matches, and removes the old hooks folder; a successful `Prepare` then sets the real launch ID. The folder lives outside `worktrees/` because `DiscoverOrphans` would walk it.

Only the parent's `Stop` reconciles against `background_tasks` (a `SubagentStop` list can omit a parallel foreground agent), and in the tracker a missing or malformed list is never read as empty. (`claude_state.go`'s `runningSubagent` reads a missing list as none running on purpose: it only decides Running versus Ready.) Teammates can't be matched by ID in that list, so shutdown is inferred by count. Read events are kept as compact `.ev` files so a restarted loom replays them (`Request.Cold`); a restored instance adopts the folder's `launch-id`, and results for another launch ID are dropped. A scan returning `ErrNoHooks` for a launch with a real ID means its folder vanished mid-run, and `ForgetSubagentsWithoutHooks` drops its rows. An agent without its metadata sidecar is hidden. Windows, non-Claude programs, a user-supplied `--settings`, or a `'` in the config dir path launch without hooks (the folder name itself escapes `'`). `claude_subagent_tracking` only decides whether `Instance.Subagents` returns rows (stored inverted as `subagentRowsHidden`, so the zero value is enabled): every Claude launch that can take hooks gets them. Opt-in contract test: `LOOM_TEST_REAL_CLAUDE=1 go test -timeout 15m ./session/subagent -run TestRealClaude` (costs money).

## Claude temp dirs

Claude keeps each session's scratchpad and task output under `<root>/<encoded cwd>/` (tmpfs on most Linux machines); `session/claude_tmp.go` wires `claudetmp/` into Pause, Kill, Resume and `SweepClaudeTemp`.
- Pause archives the dir after the worktree is removed but before it marks the instance Paused. Kill archives it when nothing failed; a tmux session tmux confirms gone counts as closed, so killing an exited agent archives at once. Both are best-effort.
- Resume restores `<name>.zip` before the agent launches, on the rebuild and relaunch-in-place paths only (a reattach launches nothing); a failed restore is a `Notice`, never a failed resume, and `Restore` creates a missing root (a reboot empties tmpfs).
- Archives live in `<configDir>/archive/claude-tmp/` (dir 0700, files 0600) and are never pruned, unless the global `config.json`'s `claude_tmp_archive_dir` relocates them under `<claude_tmp_archive_dir>/<encoded config dir>/`: `session.ClaudeTmpArchiveDir(configDir)` is the one place every archive, restore and sweep asks, rereading the setting each time, and a resume also looks in the default folder. `<name>.zip` is the only file a resume restores; a Pause, Kill or sweep that finds one already there demotes it to `<name>.<UTC stamp>.zip`.
- Claude names the dir after its physical cwd, so `claudetmp.Names` encodes both the resolved path and the stored one, and `Locate` fails closed on zero or several matches and never matches a truncated name.
- `SweepClaudeTemp`, queued by core on every workspace load (`core/claude_tmp.go`), reaps `.loom-trash-*` tombstones and `.loom-restore-*` staging dirs older than an hour and archive `*.partial` files older than a day. It takes a dir only when all of these hold: its name carries this config dir's encoded worktrees prefix and no other known config dir's (the encoding is lossy: `foo_bar` and `foo-bar` collide); it ends in a worktree timestamp and is not truncated; no record claims it; nothing in its top three levels changed within `sweepQuietPeriod`; and, rechecked just before archiving, no directory under the config dir's `worktrees*` dirs encodes to it. A dir that fails to archive is skipped until the daemon restarts.
- The daemon computes Claude's root from its own environment (`claudetmp.Root`), while each agent's Claude computes its own from the agent's, so a differing `TMPDIR` or `CLAUDE_CODE_TMPDIR` makes archiving find nothing (safe). `loom debug` prints its own environment's root. `IsolateLoomDirs` (`internal/testenv`) points `CLAUDE_CODE_TMPDIR` at a throwaway dir. Opt-in contract test (an interactive Claude in a private tmux server, since `claude -p` gets no scratchpad): `LOOM_TEST_REAL_CLAUDE=1 go test ./session -run TestRealClaude_TempDirLayout`.

## Launch environment and accounts

`session.ClaudeFullscreenEnv`, folded into `InstanceEnv` (`agent_restart.go`), launches every Claude session with `CLAUDE_CODE_NO_FLICKER=1`: Claude's classic renderer brackets every frame in DEC 2026 synchronized output, which tmux relays to an attach client as a repaint rather than scroll sequences, so the emulator's scrollback stays empty (`TestSyncOutputDefeatsEmulatorScrollback_RealTmux`, which skips below tmux 3.7, where the relay still scrolls). The env var, not `--settings`, keeps `/tui default` working per session, because Claude drops it on renderer relaunch. Any other sync-output app in either pane still can't scroll.

Instances store the account name (`InstanceData.Account`, "" = default). Every real launch resolves it through the map the model publishes with `session.SetAccountDirs` (`account_env.go`) and fails closed rather than fall back to default, which would bill the wrong subscription: `*MissingAccountError` (`MissingAccountError`) for a name the registry no longer has (its message points at R on the session to pick another account), `*AccountDirMissingError` (`AccountDirMissingError`) when the account is registered but its dir has vanished (the CLI would otherwise start a fresh, logged-out identity there; its message says to `loom account remove` and add the name again), and `*RegistryLoadError` when the registry won't load (`SetAccountDirs` carries that error alongside the map, so it is never reported as "account removed"). Every launch on an account (`launchEnv(true)`) calls `account.EnsureOnboarded`, which sets `.claude.json`'s `hasCompletedOnboarding` for a logged-in account (`oauthAccount` or `.credentials.json`), since `claude auth login` leaves it unset and the CLI would otherwise run its login screen again; a failure is logged, not fatal. `CLAUDE_CONFIG_DIR` is Claude-only: only Claude programs get it (`LaunchEnv`/`ClaudeConfigDirEnv`), so a wrapper program's sessions and the terminal pane's shell run on the default account. Two account-selection gaps stay open by design. `R` on a Paused session whose tmux session still lives reattaches it (`decideResume` → `resumeReattach`) on its old account even after another is picked: reattaching launches nothing, so `Instance.Resume` skips the account resolution that would otherwise fail closed. And an orphan recovered from disk whose tmux session is dead comes back on the default account, while a live one keeps its account (`liveSessionAccount`).

## Runtime files

- `<configDir>/worktrees/` (`~/.loom/worktrees/` for the global workspace): the worktrees; `.loom-title` sidecars sit beside them.
- `<configDir>/hooks/` (`hooks/`): per-instance Claude hook folders for status, resume and subagent tracking, one per path-escaped tmux session name; emptied at each launch, removed when an instance is killed, swept when unclaimed and its tmux session is gone.
- `archive/claude-tmp/` (or the `claude_tmp_archive_dir` relocation): zips of Claude's per-session temp dirs, minus `CACHEDIR.TAG` caches: one `<name>.zip` per paused session (restored and deleted on resume), plus permanent archives from kills, sweeps and demoted parks.

## Sub-packages

### agent

`Adapter` interface and per-program implementations (claude, aider, gemini, default fallback): trust-prompt keys, recovery flags, and `Matches(program)` checks, resolved through `Registry.Lookup`. A new agent program is an adapter here, not edits to `tmux/tmux.go` or `agent_restart.go`.

### claudetmp

Claude Code's per-session temp dir, `<root>/<encoded cwd>/<session id>/{scratchpad,tasks}`, where root is the first of `$CLAUDE_CODE_TMPDIR`/`$TMPDIR`/`$TMP`/`$TEMP` (else `/tmp`) plus `claude-<uid>`. `Root`; `DirName`/`Names` (Claude's encoding: every UTF-16 unit outside `[a-zA-Z0-9]` becomes `-`, truncated past 200 characters with a hash loom can't compute, so a truncated name never matches and such dirs are left alone); `Locate`; `Archive`/`ArchiveAs` (zip; symlinks stored as links; `CACHEDIR.TAG` dirs skipped; the source renamed to a `.loom-trash-*` tombstone, then deleted, only after the zip's rename); `Parked`; `Restore` (through `os.Root`). `Root` reads its own process's environment. No tmux, UI, app or config dependency.

### files

Stateless filesystem enumeration helpers backing the file-explorer overlay (`files/ls_files.go`, `files/recent_md.go`). Separate from `git/` because callers may operate on non-git roots (workspace terminals pointed at bare directories).

### github

Reads GitHub state through the `gh` CLI: `Query` (PRs by head branch plus open issues, one snapshot per repo), `View` (one issue with body), `CheckCLI`, `StateFor` (the pure per-session join), `SeedPrompt`/`SlugTitle`/`ParseShorthand`. `SlugTitle`'s output becomes a git branch name (loom names branches `{username}/{session_title}`), so it whitelists lowercase ASCII alphanumerics only, and a fully non-ASCII title yields a bare `gh-<n>`. No app, ui or session imports; injected executor. Core's poller drives `Query` and `StateFor`; `core.Model.FetchIssue` runs `View`; `app/state_issue_picker.go` seeds a draft from an issue (`SlugTitle`, `SeedPrompt`).

### hooks

Loom's side of the Claude Code hooks it registers on every Claude launch: `hooks/hooks.go` writes the per-launch hooks folder (`settings.json`, `launch-id`, `events/`); `hooks/scan.go` turns new event files into compact `.ev` files, replays them when needed, and stamps each event's `At` from its file name; `hooks/event.go` parses payloads, keeping only the fields loom reads. `hooks/testdata/probe-2.1.280/` holds the payloads of a live probe (see its README). No tmux, UI or app dependency.

### launch

A Claude session's launch options and their composition into, and decoding from, the agent command line (`launch/launch.go`). `Options` holds remote control, permission mode, model, the `[1m]` context suffix and effort (all baked into the program), plus the Headroom proxy, the 1h cache TTL, the branch prefix and the account, which never reach the command line; the Session Launch Options modal edits one (`overlay.LaunchOptions` is an alias). `FromConfig` (or `FromSettings`, over a `config.Settings` copy) snapshots the config's defaults, `Compose` applies them to a program, `Parse` is its inverse (the `R` restart flow recomposes from the bare program it returns), `EffectiveRemoteControl` applies Headroom proxy's exclusivity, and `RemoteControlBlocked` says when to warn before a launch. A leaf package: it imports only `config` and `session`, so the model's workspace-terminal auto-create composes a launch program without importing the UI. Changing an option: [`../docs/claude/launch-options.md`](../docs/claude/launch-options.md).

### subagent

Tracks the subagents and agent-team teammates a Claude session spawns, from `hooks` events: `subagent/tracker.go` is the state machine; `subagent/meta.go`/`subagent/readmeta.go` parse and read the `agent-<id>.meta.json` sidecars. No tmux, UI or app dependency. `subagent_hooks.go` and `hook_scan.go` wire both into `Instance`.

### git

Git worktree operations (`git/`): each session gets an isolated worktree under `<configDir>/worktrees/`, on a branch named `{username}/{session_title}` (the prefix is overridable per session: `launch.Options.BranchPrefix` → `Instance.SetBranchPrefix` → `git.WorktreeSpec.BranchPrefix`). It handles setup, diff stats (`git.DiffStats`, `git/diff.go`), parity, push, stashes, locks and cleanup.
- `Setup` writes a `.loom-title` sidecar next to the worktree directory (a sibling path, not inside the work tree, so it never pollutes `git status`) recording the original instance title; `Cleanup` removes it. Orphan discovery (`session/orphan.go`) reads it to recover the exact title and tmux session name: branch-derived titles are lossy (lowercased, dash-collapsed) and would miss the live session. Worktrees predating the sidecar degrade to the humanized branch leaf.
- `InspectTree`: intact means `.git` present and `git rev-parse` (stdout only; paths compared with `os.SameFile`) reports the path as its own top level and as a linked worktree of this repository (`--git-common-dir` matches the repo's, `--git-dir` differs from it), not still locked `initializing` by an unfinished `worktree add`. The `.git` check comes first: git in a gutted dir under `<repo>/.loom/worktrees` answers for the enclosing repo, which the top-level comparison would only report as unverified, refusing a resume a rebuild could serve.
- Locks (`git/worktree_lock.go`): `git worktree remove -f` refuses any locked tree, and an `add` killed mid-checkout leaves its tree locked `initializing` forever (its registry entry makes prune skip it and `worktree add` refuse the path, "a missing but locked worktree"). `git.RefuseLocked`, called by orphan auto-clean (`RemoveOrphanWorktree`) and by `GitWorktree.Cleanup`/`Remove` (Kill, Pause), removes that lock only once it is older than `gitWorktreeAddTimeout` plus a minute (loom kills its own add at that deadline); any other lock gets a `*git.LockedError` (`errors.Is(err, git.ErrWorktreeLocked)`) naming `git worktree unlock`, before cleanup touches anything, branch and title sidecar included. Pause and Kill check locks first (before Pause stashes, and before Kill closes the agent's session or drops a stash), so a respected lock refuses either without killing the agent; a refused Kill keeps its row (`core.Kill` returns `OpFailed`) and shows the remedy. core's `reconcileOrphans` logs a locked orphan at debug and does not count it cleaned. `clearWorktreePath` (Setup, rebuild) runs `git worktree remove -f` on whatever sits at the path (so its callers must never send it an intact tree), refuses only when `.git` survives the remove, moves a gutted tree's leftovers aside, and runs `git worktree unlock`, on any lock, only when `nothingLiveAt` holds (absent, not a directory, or no `.git`; one that cannot be stat'ed counts as live). `worktree add` runs under `gitWorktreeAddTimeout` (`addWorktree`), not the short tick budget whose kill left that lock.
- Stashes: `refs/stash` is shared by every worktree of the repo, and `git stash drop` only takes a stash@{N} position, which shifts under concurrent sessions. `DropStash` checks the SHA git reports dropping, stores a wrong entry back (retrying a failed store once; after that its error names the commit and the `git stash store` that restores it), and retries; `StashListed` fails, never answering "not listed", when the list can't be read; `ApplyStash` returns `git.ErrStashNotDropped` when the drop failed after a good apply.
- Tests: `session/git/worktree_inspect_test.go`, `session/git/worktree_hardening_test.go`, `session/git/stash_hardening_test.go`.

### vt

The embedded terminal emulator backing pane display: `vt/vt.go` defines the `Emulator` interface; `vt/xvt.go` (`session/vt/xvt.go`) is the `github.com/charmbracelet/x/vt`-backed implementation (vendored); `vt/altfilter.go` holds `vt.NewAltScreenFilter`. It decouples rendering and scrollback from `tmux capture-pane`, so panes can live-scroll and forward mouse and paste input. x/vt only accumulates scrollback on the primary screen, while tmux attach clients enter the alternate screen at attach and never leave it, so the output pump writes through the filter, which strips alt-screen mode switches (1047/1049/47) from the client stream. `vt/xvt.go` registers `Callbacks` that fire inside `emu.Write`, under the wrapper's write lock. One known vendored bug: the OSC-title parser truncates titles containing non-ASCII bytes (it terminates on the lead byte of a multi-byte UTF-8 sequence), so `TmuxSession.PaneTitle` rejects invalid UTF-8 rather than forward mangled bytes to the host terminal.
