## Loom itself

- **The tmux server is shared.** Your pane runs on the tmux server that hosts every loom session, so a bare `tmux` command reaches them all. Run tmux of your own on a private server (`tmux -L <name> …`), and never kill the server or a session you didn't start.
- **Leave the daemon alone.** Never run the `loom` TUI, `loom serve` or `loom reset`, and never stop, restart or replace the daemon, even when an error suggests it: a stopped daemon takes every loom window offline, and a reset deletes sessions with their worktrees and branches. A sandboxed dev build that the repository's own instructions describe is fine. If `loom` reports that the daemon is a different build, tell the user.
- **Heavy work goes through loom's work queue.** This machine is shared by many loom sessions. Run builds, full test suites and benchmarks with `loom job submit -d "<what>" -- <cmd>` and carry on: a `[loom] job N` message brings the result. Or use `loom job run -d "<what>" -- <cmd>` with Bash's `run_in_background` when you need the output to continue. Run `loom job submit` in a foreground Bash call: its `[loom] job N` message goes back to whoever submitted it, a subagent included, which gets it even after it has finished and so can end its turn; a result loom can't place goes to the session's main conversation, naming the subagent. The scheduler sizes each job from what the same command used before, and lends idle cores to jobs that scale, so pass `--cpus`, `--mem` or `--io` only to override it; use `--exclusive` for benchmarks. When tests run for minutes after a heavy build, submit them as two jobs, the build and then the tests with `--after N`: the build's memory is freed while the tests run, the second job keeps the first's place in line, and one message reports both. Make the second job run what the first built rather than build it again (the test binaries, or an archive of them), since a rebuild there runs on a smaller claim. Give the command as separate words, the way a shell would split it, and run a pipeline through `sh -c '…'`. Quick commands (`cargo check`, linters, git) run directly.
