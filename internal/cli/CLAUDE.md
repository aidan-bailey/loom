# internal/cli

The `loom workspace`, `loom account`, `loom session`, `loom web`, `loom sweep` and `loom job` subcommands (`WorkspaceCmd` in `workspace.go`, `AccountCmd` in `account.go`, `SessionCmd` in `session.go`, `WebCmd` in `web.go`, `SweepCmd` in `sweep.go`, `JobCmd` in `job.go`) and the daemon half of `loom reset` (`Reset`, `reset.go`): clients of the loom daemon. Each joins it through `Join` (`join.go`), which `main.go` sets to the TUI's startup join (`joinCLI`), makes its request, prints the answer and exits. `workspace migrate` stays in `cmd` (`cmd.MigrateCmd`) and writes `state.json` itself, under the lock.

## Rules when modifying this package

- **Change the registries only through the daemon's requests** (`Register`, `Unregister`, `RenameWorkspace`, `SetLastUsed`, `AddAccount`, `SetDefaultAccount`, `RemoveAccount`, `Reset`). The daemon serves what it wrote at once (a workspace added is served, one removed unloaded, one renamed keeps its ID); a command writing a registry file itself leaves the daemon serving the old state until its next reread. **Enforced** for `workspace add` by `TestWorkspaceAdd_TheDaemonServesItAtOnce`, and for the others by their `TestWorkspace…`/`TestAccount…` tests, which assert the daemon's state.
- **Wait for a round the daemon runs by its data, never by the next event.** An `AccountsChanged` can be another round's (one already in flight, a usage probe), so `sync` waits until every account's `SyncReport.At` is from its own refresh (`synced`) and `list` until every sample is from its own round or failed (`probed`), up to `accountWait`; a request with a `ReqID` (`Reset`) waits for its `Reply` (`awaitReply`). **Enforced** by `TestAccountSync_LinksNewEntriesForEveryAccount` (an add's refresh still in flight) and `TestAccountList_ShowsAnOlderSampleWithItsAge`.
- **Follow a cast with a request when the command exits next** (`requestRefresh`): a cast has no reply, and the connection closing at once could drop it. **Convention** — a login the daemon never rereads; the tests' in-memory pipe delivers every write, so `TestAccountLogin_TheDaemonRereadsTheAccountsAuth` can't show the loss.
- **Write the daemon's notices to stderr, but not one naming the command's own request** (`withDaemon`, `client.events`, which hands that one to the command): a command can be the first client to connect, and the daemon hands it the notices kept for the first client (its boot's); a request's notice repeats what its `Reply` says, which the command reports. **Enforced** for the repeat by `TestReset_AFailureIsReportedOnce`; **Convention** for the boot's — a warning nobody sees.
- **Keep the test daemon hermetic: its `CLAUDE_CONFIG_DIR` and `HOME` are the test's, its fake Claude answers its auth read, and a test checks an account's links before it writes into its dir.** A daemon that can't learn its main config dir falls back to them; one that fell back to `~/.claude` linked the developer's real files into a test account, and a test's write through a link overwrote the developer's `settings.json`. Write test files with `writeNew`, which refuses a link. `TestMain` points `LOOM_TMUX_SOCKET` at a private server for the whole run, since a test daemon's background jobs outlive its `Stop` and the test's own `t.Setenv`. **Enforced** by `requireIsolatedClaude` (`serveDaemon`), the main-dir check in `accountsFixture.serve`, and `linksIntoMain` (`accountsFixture.account`, `created`); **Convention** for the tmux socket — a late job reaching the developer's server.
- **Let `remove --force` alone override the in-use and unshared-files refusals, report what it overrode, and still confirm; the daemon checks its live sessions again.** `--yes`/`-y` skips only the prompt. The unshared-files check runs, and reports, before the prompt, which says "delete `<dir>`" only when `Registry.OwnedDir` says loom owns the dir. **Enforced** for the flags, the refusals and their order by `TestAccountRemove_…` (`internal/cli/account_test.go`); **Convention** for the prompt's wording — a user told a dir will be deleted that is left, or the reverse.
- **Leave linking to the daemon, which validates the main dir first** (`account.ValidateMainDir` in `Registry.Create` and `syncMainDir`); `sync` refuses a main dir the daemon reports as unsafe rather than print stale reports. **Enforced** by `TestAccountAdd_RefusesAnUnsafeMainDir` and `TestAccountSync_RefusesAnUnsafeMainDir`.
- **Refuse `add`, `list`, `sync` and `login default` when the shell's own `CLAUDE_CONFIG_DIR` resolves inside `<AccountsDir>/<name>`** (`guardAgainstAccountEnv`, `accountFromEnv`): from an account's agent pane, the inherited env would log the wrong identity in as default. `use`, `remove` and `login <account>` still work. **Enforced** by `TestAccountCmds_RefuseWhenRunningAsAnAccount` and `TestAccountCmds_NamedAccountOpsStillWorkUnderAccountEnv`.
- **Refuse `login default` when the shell's main config dir is not the daemon's** (`sameMainDir`, comparing canonical paths): the login goes to the shell's `CLAUDE_CONFIG_DIR` (else `~/.claude`), and one no session uses logs nobody in. **Enforced** by `TestAccountLogin_DefaultRefusesAnotherMainDirThanTheDaemons` and `TestAccountLogin_DefaultRunsInTheDaemonsMainDir`.
- **Refuse `login` for a registered account whose dir is missing.** `claude auth login` would recreate it bare, unlinked and logged out; the message says to `remove` the account and `add` it again. **Enforced** by `TestAccountLogin_RefusesWhenTheAccountDirIsMissing`.
- **Wrap the login child in `signal.Notify`/`signal.Stop`, never `signal.Ignore`** (`runWithChildSignals`). An ignored SIGINT is `SIG_IGN` at the OS level and survives `exec`, so Ctrl-C during `claude auth login` would reach neither loom nor claude. **Enforced** by `TestRunWithChildSignals_DoesNotLeakSignalIgnoreIntoTheChild`.
- **Read the Claude binary `login` runs from the global dir's `config.json`** (`claudeProgram()`, through `config.GetGlobalConfigDir()`), not `LOOM_HOME`'s. **Enforced** by `TestClaudeProgram_PrefersTheGlobalConfigDirOverLoomHome` and `TestAccountLogin_UsesTheProgramConfiguredInTheGlobalDir`.
- **Warn about a credential override in `add` and `list` from the daemon's environment (`warnDaemonOverride`, `Core.CredentialOverride`), and in `login` from the command's own (`warnLoginOverride`).** Sessions run in the daemon's environment, a login's claude in the command's; with one set every account bills as it. `use` and `sync` run no session and stay quiet. **Enforced** by `TestAccountList_WarnsAboutTheDaemonsCredentialOverride`, `TestAccountAdd_WarnsAboutTheDaemonsCredentialOverride` and `TestAccountLogin_WarnsAboutItsOwnCredentialOverride`.
- **Wait for `loom session new` in one loop for its Reply, its `Started` and its own notices (`awaitStart`).** A refused Create is the Reply's `Err`, a failed start one or two `Notice{Req}` (the daemon has removed the instance by then), a success `Started{Req}` after the initial prompt; `client.events` hands a command the notices naming its requests rather than writing them. A wait for the Reply alone can drain the start's notice and then wait for a `Started` that never comes. **Enforced** by `TestSessionNew_AFailedStartFailsAndLeavesNoSession` and `TestSessionNew_ReturnsOnceTheSessionRuns`.
- **Wait for `loom session send` in one loop too (`awaitSend`): its Reply (queued, or refused), then with `--wait` the `Answered` naming it or a `Notice{Req}` saying its turn will not end.** The Reply comes once the mod has queued the message, the answer only when the turn ends, and either can share a batch with the other. **Enforced** by `TestSessionSend_WaitPrintsTheAnswer`, `TestSessionSend_ReturnsOnceQueued`, `TestSessionSend_RefusesWithoutAMod` and, for the Notice, `TestSessionSend_AStopAfterQueuedSaysItWasDelivered`.
- **Let an interrupt end a command's wait, never the daemon's work** (`client.ctx`, which `await` selects on). `new` cancels it on SIGINT and says the daemon is still starting the session, and `send` says whether its message was already queued; without the `ctx.Done()` case Ctrl-C waits for the next event. **Enforced** by `TestSessionNew_AnInterruptLeavesTheDaemonStarting`, whose post-checkout hook holds the start so the interrupt lands mid-wait, and `TestSessionSend_AnInterruptAfterQueuedSaysItWasDelivered`.
- **Name a session by exact title among the workspace's rows, never a prefix, never the workspace terminal, and refuse a shared title unless `--id` picks one whose title still matches (`findSession`).** A prefix or a stale ID acts on another session. **Enforced** by `TestFindSession` and `TestSessionOps_NameASessionExactly`.
- **Take a new session's checks and launch account from `core` (`CheckRoom`, `CheckWritable`, `CheckNewTitle`, `ChooseLaunchAccount`), the TUI's own source,** adding only what naming by title needs (a title the workspace already holds is refused). A check written here drifts from the TUI's. **Convention** — a session the TUI would have refused, or one on another account than the modal would pick.
- **Ask before `session kill`, and let `-y` alone skip the question; anything but `y`/`yes`, EOF included, kills nothing and exits 1.** A script piping no stdin must not kill. **Enforced** by `TestSessionKill_AsksFirst` and `TestSessionKill_YesSkipsTheQuestion`.
- **Leave a web setting's and a device name's validation to the model: `loom web` sends `ConfigureWeb`, `PairDevice` and `RevokeDevice` and prints the model's refusal as its error.** A check written here drifts from the one the stored `web.json` is held to, and a refused setting must leave the stored one as it was. **Enforced** by `TestWebEnable_PassesTheDaemonsRefusalOn` and `TestWebPair_RefusesAPairedNameAndABadOne`.
- **Wait for `loom web enable` until the daemon reports the address it was asked for, serving or failed (`webSettled`), up to `webWait`.** The `WebView` holds the previous state until the web layer rebinds, so the first event after the request can report the old listener or the old error as the new one: take only a `Web()` whose `Rev` is past the one read before the call. Send `ConfigureWeb` once, even for the stored values, since every call bumps `Rev` and the layer rebinds on that, which retries a failed bind; send none when `servesAlready`, which would drop the open streams for nothing. **Enforced** by `TestWebSettled`, `TestWebEnable_SaysWhenTheDaemonDoesNotAnswer`, `TestWebEnable_AgainRetriesAFailedBind` and `TestWebEnable_WhenItAlreadyServesChangesNothing`.
- **Follow a job in one loop (`jobFollower.run`): read its view first, then copy what `output.log` gained, and end only on a finished view, the daemon's loss or the command's interrupt.** A job seen finished has a complete log only when the view was read before the log, and the log grows with no event, so the loop also polls (`logPoll`). A wait on the next event alone stalls on a running job; a log read before the view can miss a finished job's last lines. **Enforced** by `TestJobRun_FollowsAJobToItsExitCodeAndLogsReadItBack` and `TestJobCopyLog_CopiesOnlyWhatIsNew`; **Convention** for the order — a missing last line.
- **Exit with the job's own code, through `*ExitError`, which `main.go` turns into the process's exit code: the job's exit code, 128 + N for a job killed by signal N (`signalExit`: `unix.SignalNum` of `Exit.Signal`, else the n of a `SIG<n>` name, in `job_unix.go`), `exitNotRun` (125) for a job that was lost, could not start, was cancelled, or was killed by a name the platform does not map.** A shell or a Bash tool reads the code as the command's own, and a follower that exits 1 for all of them hides whether the build failed or never ran. **Enforced** by `TestJobOutcome`, `TestJobInterruptCode` and `TestJobWait_ACancelledJobExits125`; **Convention** for the `ExitError` branch of `main` — every outcome exiting 1.
- **Let an interrupt end the follower, never the job (`notifySignals`: `signal.Notify` for SIGINT, SIGTERM and SIGHUP, released with `signal.Stop`), and exit 128 + the signal's number.** A Bash timeout sends SIGTERM to `loom job run`, and the build it queued is wanted; the follower asks for a message (`NotifyJob`) only for a job that has an owner and has not ended, and says so only when the daemon took the request. **Enforced** by `TestJobRun_AnInterruptWithNoOwnerSaysSo` and `TestJobRun_AnInterruptAsksForAMessageWhenTheJobHasAnOwner`.
- **Send `os.Environ()` as the job's environment, as data (`submission`), and refuse every `loom job` command on Windows with `sched.ErrUnsupported` (`beginJob`, `checkPlatform`).** The daemon starts the job in the submitter's environment, never its own; it has no scheduler on Windows, and the signal mapping sits in `job_unix.go` and `job_windows.go`. **Enforced** by `TestJobSubmission_CapturesTheShellItRunsIn` and `TestJobCheckPlatform`; **Convention** for the cross-build — `GOOS=windows CGO_ENABLED=0 go build ./...` after touching those files, since only the release builds Windows.
- **Start the test daemon's jobs through the test binary: `TestMain` calls `sched.MaybeRunTestShim()` first, and `serveDaemonOn` installs `sched.TestRunner()` with `SetJobRunnerForTest` before `Boot`.** A job in a test is a real process group of this binary; a runner installed after `Boot` would not be the one that adopts and starts jobs. **Convention** — every job test failing with a job that could not start.
