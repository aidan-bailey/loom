# internal/testenv

Test-only isolation and the repo-wide enforcement tests: `IsolateLoomDirs`/`MustIsolateLoomDirs` (`testenv.go`), which point `LOOM_HOME`, `LOOM_GLOBAL_DIR`, `CLAUDE_CODE_TMPDIR` and `CLAUDE_CONFIG_DIR` at a throwaway dir for a whole test binary, plus `TestEveryConfigReachingPackageIsolatesLoomDirs` (`testenv_test.go`), `TestTUIHoldsNoModelObject` (`instance_enforce_test.go`) and `TestNoProductionCallsOfTestSeams` (`seams_enforce_test.go`). Only test code imports this package.

## Rules when modifying this package

- **Root every enforcement scan at the repo (`filepath.Abs("../..")`, then `require.FileExists` on `go.mod`) and read source with go/parser.** A wrong depth must fail loudly rather than scan nothing. The whole-tree walks (`TestNoProductionCallsOfTestSeams`, `TestEveryConfigReachingPackageIsolatesLoomDirs`) skip `vendor/` and dot-dirs, since `.loom` holds other branches' worktrees; `TestTUIHoldsNoModelObject` walks only `app/`, `ui/` and `script/`. The scans read files from disk, so `go test -overlay` is invisible to them, and none skips `testdata/`: a committed fixture holding a violation fails them. **Convention** — an enforcer that silently passes an empty tree.
- **A new model object the TUI must not hold joins `modelObjects` in `instance_enforce_test.go`.** `TestTUIHoldsNoModelObject` walks `app/`, `ui/` and `script/` and fails only on the names listed there (`session.Instance`, `session.Storage`, `core.Model`, `core.New`, `core.Start`, `core.Job`, `config.WorkspaceRegistry`, `account.Registry`, …), resolved through each file's own import name: a type left off the list can be held by the TUI, whose copies then go stale and whose mutations race the daemon's loop. **Enforced** by `TestTUIHoldsNoModelObject` once the name is listed.
- **Every package whose tests can reach `config` calls `IsolateLoomDirs` or `MustIsolateLoomDirs` from its `TestMain`; `config` itself is the one exemption.** Without it a test resolves `~/.loom` and reads or writes the developer's live `workspaces.json`, `state.json` and worktrees, a real Claude root holding live scratchpads, and the developer's `~/.claude` as the main config dir test accounts link to (`account.MainDir`), which a test's write into an account dir once overwrote through a link (`HOME` stays, for git). A new package's first test needs a `TestMain` (copy any `testmain_test.go`); a test needing its own dirs still `t.Setenv`s over them. `config`'s own `TestMain` points `HOME` at a throwaway instead, so its tests assert the default by computing `os.UserHomeDir()`, never by touching it. **Enforced** by `TestEveryConfigReachingPackageIsolatesLoomDirs`, which walks the import graph, and for the main config dir by `TestIsolateLoomDirs_KeepsClaudesMainDirOffTheRealHome` and `TestMainDir_IsTheIsolatedOneInTests` (`account`); its `callsIsolate` accepts the call in any `*_test.go` file, so that it runs from `TestMain`, before every test, is **Convention**.
- **Keep the `Env…` constants in `testenv.go` equal to the names `config`, `claudetmp` and `account` use, and import no loom package, tests included.** The scan counts test imports, so importing one that reaches `config` here makes every package whose tests import this one reach it; each package's tests assert the names agree instead, and a renamed variable here would isolate nothing. **Enforced** by `TestTestenvNamesMatchConfig` (`config`), `TestEnvNameMatchesTestenv` (`session/claudetmp`) and `TestMainDir_IsTheIsolatedOneInTests` (`account`).
- **Adding an enforce test?** Root it at the repo as these do, resolve aliased and dot imports per file (`internal/exec/command_enforce_test.go:rawGitGhExecs` is the model), keep fixtures in memory or under `t.TempDir()`, and pin the matcher with a detection table such as `TestRawGitGhExecs_Detection`, which none of this package's scans has yet: without one a refactor can turn an enforcer into a test that never fails. **Convention** — guide: [`../../docs/claude/adding-an-enforce-test.md`](../../docs/claude/adding-an-enforce-test.md)
