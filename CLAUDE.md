# CLAUDE.md

Loom is a terminal UI, in Go on Bubble Tea, for running AI coding agents (Claude Code, Aider, Codex, Amp) in parallel, each in its own git worktree and tmux session, under one daemon per global config dir (`loom serve`) that owns every session and outlives every TUI.
It was forked from claude-squad at v1.0.17 and has diverged since: [`NOTICE.md`](NOTICE.md).

## Design principles

- **One owner of state.** The daemon's model owns sessions and writes `state.json`; clients hold copies and change it only by request.
- **Fail closed.** When tmux, git or a file can't answer, change nothing and say so: no guessed status, no kill, no rebuild, no fallback account.
- **Identity, not position.** Act on an `InstanceID`, a canonical path or an exact tmux target, never on the selection, a list index or a prefix match.
- **Nothing silently lost.** Undecodable records, stashes, scratchpads and unshared account files are kept and reported, never dropped.
- **Compatibility:** `state.json` stays downgrade-safe (versioned records, unknown ones written back unchanged), the wire is versioned (`rpc.Protocol`), and claude-squad's names (`~/.claude-squad`, `claudesquad_`, `CLAUDE_SQUAD_*`) still work.
- Within these, refactor freely: the Go packages have no outside users. The CLI, `config.json`, the Lua API and the wire between builds do.

## Always / Never

- **Never run loom itself (`./loom`, `go run .`) or `loom serve stop` in a loom pane; run dev builds through the `loom-dev` skill (`go run ./tools/loomdev`).** A dev build there joins or replaces the user's daemon, `loom serve stop` quits every open TUI, and on 2026-09-23 a second loom's startup sweep killed all 20 sessions on a shared tmux server. **Enforced** in part by `replaceGuard` and the nesting guard (`TestReplaceGuard`, `TestServeCmd_GuardsTheServerItPins`); **Convention** for the rest.
- **Never remove `loom.lock`.** The daemon's flock is on its inode, so a recreated file lets two daemons run and drop each other's records. **Convention**.
- **Invoke tmux only through `tmux.Command`/`tmux.CommandOnSocket`, with exact targets (`SessionTarget`, `PaneTarget`).** A raw exec reaches whatever server encloses the process, and a bare `-t` prefix-matches another agent's session. **Enforced** by `TestNoRawTmuxExec` and `TestTmuxTargetsAreExact`.
- **Build git and gh subprocesses only with `internalexec.GitCommand`/`internalexec.GhCommand` (`internal/exec/command.go`).** Callers classify git's English errors, and a user's locale misclassifies them silently. **Enforced** by `TestNoRawGitGhExec`.
- **The TUI (`app/`, `ui/`, `script/`) holds no model object, and `core` imports no UI.** The model runs in another process; a held pointer goes stale and a mutation races its loop. **Enforced** by `TestTUIHoldsNoModelObject` and `TestCoreImportsNoUI`.
- **No test touches the real `~/.loom` or the user's tmux server.** Every package whose tests reach `config` calls `internal/testenv.IsolateLoomDirs` from its `TestMain`; real-tmux tests run on a private server. **Enforced** for the dirs by `TestEveryConfigReachingPackageIsolatesLoomDirs`; **Convention** for tmux — a test that kills live agents.
- **Never edit generated files:** `core/rpc/methods_gen.go` (`go generate ./core/rpc`), `docs/specs/protocol.md` (`go test ./core/rpc -run TestProtocolReference -update`), `CHANGELOG.md` (git-cliff). **Enforced** by `TestGenerated_IsFresh` and `TestProtocolReference`.
- **Keep platform code in `_unix.go`/`_windows.go` files, and after touching syscalls, process control or sockets run `GOOS=windows CGO_ENABLED=0 go build ./...`.** GoReleaser builds Windows (`.goreleaser.yaml`) but CI's matrix doesn't (`.github/workflows/build.yml`), so a Unix-only call breaks only the release. **Convention**.
- **Keep scratch files out of the worktree; commit with explicit `-- <paths>`, never `-a`, `git add -A` or `.`.** Loom runs `git add -N .` in every session worktree on each diff probe (`session/git/diff.go`), so a file that lands here even briefly keeps an index entry after you delete it (`git status` shows ` D`): delete it, then `git rm --cached` it. **Convention** — details in [`docs/claude/testing-pitfalls.md`](docs/claude/testing-pitfalls.md).

## The root package (`main.go`, `serve.go`, `daemon_client.go`)

- **`replaceGuard` refuses to replace the daemon from a `loom_*`/`claudesquad_*` session on the daemon's tmux server, or on any server when the daemon named none (then only `LOOM_GLOBAL_DIR` lets it through); neither `LOOM_TMUX_SOCKET` nor `LOOM_ALLOW_NESTED` gets past it.** A loomdev sandbox passes because its daemon's server is its own. **Enforced** by `TestReplaceGuard`.
- **Pin the daemon's tmux server (`tmux.UseServer`) before anything touches tmux: in `serve.go`, in `daemonLink.join`, and in `reset`.** An unpinned process finds every session dead on its own server. **Enforced** by `TestJoin_PinsTheDaemonsTmuxServer`, `TestServeCmd_GuardsTheServerItPins` and `TestResetCmd_SweepsTheServerADaemonWouldPin`.
- **`main.go` sets `cmd.StateWriteGuard` to `refuseWhileServed`**, since `cmd` can't import the daemon's packages. **Enforced** by `TestStateWriters_RefuseWhileTheDaemonRuns`.
- **Keep `version = "X.Y.Z"` in `main.go` in exactly that shape.** `flake.nix` and `.github/workflows/release.yml` extract it by pattern. **Convention** — the Nix build throws and no release is cut.
- The daemon's own rules: [`internal/daemon/CLAUDE.md`](internal/daemon/CLAUDE.md).

## Verification

Not exhaustive: the package `CLAUDE.md` files name the tests that guard each rule.

- `CGO_ENABLED=0 go test ./...`. Builds run with CGO off, and a plain `go test` fails with `cgo: C compiler "gcc" not found` where only clang is installed. The Go version is `go.mod`'s `go` directive; there is no `toolchain` line.
- Race: `CC=clang CGO_ENABLED=1 go test -race ./...` (drop `CC=clang` where gcc exists). CI runs it.
- Format: `gofmt -w $(git ls-files '*.go' | grep -v '^vendor/')`, and check with `gofmt -l` on the same list. Never `gofmt -w .`: it rewrites vendored files.
- Lint: CI pins golangci-lint v1 in `.github/workflows/lint.yml`. The dev shell's v2 rejects the repo's `.golangci.yml` and `--fast`, so run `CGO_ENABLED=0 go vet ./...` locally, say plainly that golangci-lint was skipped, and leave the config alone; or run the pinned release binary from GitHub with `--new-from-rev=origin/main`. CI checks only the lines a push changes, so a gofmt realignment of an aligned block of one-line methods brings its undocumented neighbours into revive's scope: keep the block's widest line, or document what moves.
- End to end, after changing the daemon, the join or a lifecycle: `go test -tags e2e ./e2e/...` (needs tmux; no CI job runs it).
- Docs: `go test ./...` fails on their structure through `TestRepo_ClaudeMDStructure`; `go run ./tools/claudemd -v` shows the budgets' headroom, and `go run ./tools/claudemd -idents` the symbols it can't find (failing only under `LOOM_CLAUDEMD_STRICT=1`).
- CI: `.github/workflows/build.yml`, `.github/workflows/race.yml` and `.github/workflows/lint.yml` run only when Go files, `go.mod`, `go.sum` or the workflow change, so a docs-only commit runs none of them; `.github/workflows/docs.yml` runs the CLAUDE.md lint on every push and pull request to `main`.
- Nix: `nix build .#loom` runs the tests in a sandbox with no TZ, locale or `$TMUX`, and stops at the first failing package; `tools/` and `e2e/` are excluded. Guide: [`docs/claude/nix-build-failures.md`](docs/claude/nix-build-failures.md).

## Tests

- testify (`testify/assert`, `require`); temp dirs for every file; `TestMain` initializes logging, runs, and calls `os.Exit`. Seams: `cmd.Executor`, `tmux.PtyFactory`, and the `NewSessionWithDeps()`, `NewAttachClientWithDeps()` and `NewTmuxSessionWithDeps()` constructors.
- Build fixtures through the production path (real constructors, `ReconcileAndRestore`, a started instance), and give fakes the real component's geometry: a fixture that skips a step production runs has hidden a bug from every review, more than once.
- Pin both sides of every guard (the case it spares and the ordinary case it must still act on), and mutation-check each term of a compound guard separately.
- A long `TMPDIR` breaks tmux sockets (`sun_path` caps a socket path at 108 bytes); real-tmux tests keep their socket paths short.
- More traps, and how to prove a regression test goes red: [`docs/claude/testing-pitfalls.md`](docs/claude/testing-pitfalls.md).

## Code conventions

- Wrap errors with context: `fmt.Errorf("context: %w", err)`. The module path is `github.com/aidan-bailey/loom`.
- Private struct fields, public methods; keep goroutines few (tmux monitoring and the model's loop hold most of the concurrency).
- Log through `log.For("subsystem")`, which tags every record `subsystem=…`.

## Claude Code automation

- **Skills:** `loom-dev` (run, drive and screenshot a dev build safely from inside loom)
- No commands, hooks or rules files are checked in under `.claude/`, and the lint refuses a CLAUDE.md or a rules dir there, which would load without its checks. A CLAUDE.local.md is personal: the lint leaves it alone, so keep it out of commits.
- Explore and Plan subagents load no CLAUDE.md. When delegating to them, restate the rules that matter in the prompt: scratch files outside the worktree, never run loom in a pane, and the package rules of the files they touch. General-purpose subagents load the files.

## Commits and releases

- Conventional commits, typed as `cliff.toml` groups them (`feat`, `fix`, `refactor`, `docs`, `perf`, `test`, `build`, `chore`, `ci`, …) and scoped by package short name (`core`, `app`, `rpc`, `tmux`, `serve`; several joined with commas).
- **Release by bumping `version` in `main.go` and prepending a scoped changelog section (`git cliff <prev>..HEAD --tag vX --prepend CHANGELOG.md`), never by regenerating `CHANGELOG.md` whole.** Tags lag the released versions, and git-cliff silently merges every untagged release into one. **Convention** — guide: [`docs/claude/releasing.md`](docs/claude/releasing.md).

## Conventions for CLAUDE.md files

- **Self-sufficiency.** Every rule states inline the minimum context needed to apply it correctly. Do not write phrases that point readers to another file — they rot, and `CLAUDE.md` is auto-loaded but `README.md` is not.
- **Rules vs facts.** `CLAUDE.md` holds *rules* (what must / must not happen when modifying code). `README.md` holds *facts* (what the package is, structure, public API); facts spanning packages go in [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md), user-facing ones in `USAGE.md`. Some duplication on critical facts that drive rules is the right cost.
- **Procedures live in `docs/claude/`.** If a rule needs more than ~3 lines of supporting context, write a procedure at `docs/claude/<task>.md` and link to it from the rule.
- **Rule shape.** What to do; why, in one clause; what breaks and how silently; then **Enforced** by a named test, or **Convention** with the silent wrong result. Present tense. Name, don't count. Name the file that holds a config value or tool version instead of restating it. Write paths from the repo root or beside the doc. History stays in git.
- **Coverage.** A package `CLAUDE.md` covers its subtree; every Go package needs one there or in a parent below the root, or an exemption with a reason in `tools/claudemd/lint.go`.
- **Size budgets.** Root `CLAUDE.md` ≤150 lines and 16,000 bytes; package `CLAUDE.md` ≤100 lines and 20,000 bytes; no line over 1,200 bytes. Enforced by `tools/claudemd` (`go test ./...`, `go run ./tools/claudemd`, and CI's Docs workflow). Check the headroom (`go run ./tools/claudemd -v`) before planning rule additions, and move context into a guide rather than raise a budget.
- **The lint checks structure, not truth.** It catches a path, a test name or a file-and-symbol reference that no longer resolves, but a moved symbol named plainly, a count, or a rule that is no longer true passes it forever. Re-run it after merges, and re-verify with [`docs/claude/auditing-claude-md-currency.md`](docs/claude/auditing-claude-md-currency.md). Deleting a package or retiring a concept means grepping every `CLAUDE.md`, README and guide for it.
- **When entering an unfamiliar package**, read its `README.md` once for orientation before broad exploration.
- `CLAUDE.md` is per worktree: a session in a worktree reads that branch's files, so rules land on `main` only when the branch merges. Commit a rule with the work that taught it; when a written rule is broken again, make it mechanical ([`docs/claude/adding-an-enforce-test.md`](docs/claude/adding-an-enforce-test.md)). Repo lessons go here and in `docs/claude/`, not in personal memory.
- Not adopted yet, because loom has nothing for them: ADRs and an ADR index (design history stays in `docs/superpowers/specs/`), an issue-label table, a hook-launch check (no hooks are checked in), a `/distill` command, and anchor checks in links.

## Updating docs/claude/

Before ending the turn on non-trivial work, evaluate: did I (or the user) discover a fact worth recording for future sessions? Did I make a mistake whose rule isn't captured anywhere yet? Did a workflow take longer than it should have because the path wasn't documented?

If yes, write or extend a file in `docs/claude/`, add it to [`docs/claude/INDEX.md`](docs/claude/INDEX.md), and commit as part of the work. Bar: "a future session would have done better with this knowledge." If unsure, skip — undocumented beats noise.
