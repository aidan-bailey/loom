# script

The sandboxed Lua engine (gopher-lua) behind every key in the default state: the built-in keymap in `script/defaults.lua`, user scripts from `~/.loom/scripts/*.lua`, and the `cs`/`ctx`/instance/worktree API the app's script host serves. Full reference in [`README.md`](README.md); the API's truth is [`../docs/specs/scripting.md`](../docs/specs/scripting.md).

## Rules when modifying this package

- **Run every engine dispatch and resume under `engine.mu`.** A Lua `LState` is not goroutine-safe, and the TUI drives the engine from `tea.Cmd` goroutines while Update keeps running. **Convention** — Lua state corrupted by two goroutines, which only `CGO_ENABLED=1 go test -race` finds (`TestScriptHost_ConcurrentNavAndRead`, `app/script_dispatch_race_test.go`, covers the host's side).
- **Change instances only through intents that yield until their Reply.** `inst:kill()`, `inst:pause()`, `inst:resume()`, `inst:send_prompt()` and `ctx:new_instance{}` enqueue an `InstanceOpIntent` or `CreateInstanceIntent` and resume with a `ResumeValue`; userdata holds views and the host holds no `*home`, so nothing inside the engine can reach `m.list` or an instance. tmux primitives (`preview`, `send_keys`, `tap_enter`) act by the view's session name. **Enforced** by `TestTUIHoldsNoModelObject` (`internal/testenv/instance_enforce_test.go`), which covers `script/`, by `TestLifecycleMethods_YieldUntilTheHostResumes` (`script/lifecycle_test.go`) for the lifecycle calls, and by `TestCtxNewInstancePassesPromptThroughConstructor` (`script/engine_test.go`) for `ctx:new_instance`.
- **Refuse a yielding call wherever it can't yield** (`yieldable`): inside `pcall`/`xpcall`, a callback, a precondition or a coroutine the script made. A script must not catch a lifecycle call's error, and a yield there would resume the wrong thread. **Enforced** by `TestYieldingMethods_RefuseWhereTheyCannotYield`.
- **Keep the sandbox to `base`, `string`, `table`, `math` and `coroutine`, with the escape hatches stripped and `print` replaced.** `dofile`, `loadfile`, `load`, `loadstring`, `require`, `string.dump`, `collectgarbage`, `setfenv`, `getfenv`, `newproxy` and `_printregs` reach files, bytecode or other environments; base's `print` writes to stdout and corrupts the TUI's alt screen, so the replacement routes to the script log. **Enforced** by `TestSandboxBlocksEscapeHatches` (`script/engine_test.go`), `TestOpenSandbox_StripsEscapeHatches` and `TestOpenSandbox_PrintRoutesToScriptLog` (`script/sandbox_test.go`).
- **Log script output synchronously through `log.For("script")`** (`Engine.logScript`), tagged with the file being loaded (`curFile`) or the file whose handler runs (`curActionFile`). `DrainLogs` is a bounded test capture, never a delivery path. **Enforced** by `TestLogScript_ReachesStructuredLogger` and `TestLogScript_RuntimeLinesCarryTheActionFile`.
- **Keep bindings last-write-wins in load order, with `ctrl+c` reserved.** `cs.bind` and `cs.register_action` overwrite each other across every script; `script/defaults.lua` loads first (`LoadDefaults`, from the app's `initScriptsIn`), then the user scripts in filename order, so a user binding wins; a reserved key is dropped with a warning. **Enforced** for a repeated `cs.bind` by `TestCsBindOverridesExisting` and `TestEngineLaterBindOverwritesForDuplicateKey`, for a user script loaded after the defaults by `TestUserScriptOverridesDefault`, and for reserved keys by `TestCsBindReservedIsDroppedWithWarning`; **Convention** for `cs.register_action` against `cs.bind`, the order `initScriptsIn` loads in, and filename order — a user binding silently losing to a default or to another script.
- **Changing a key in `script/defaults.lua`?** It is the keymap's truth. `keys.GlobalkeyBindings` holds only the keys with a menu or help entry, and each of those must stay bound in `script/defaults.lua`; keys bound only there (`tab`, `c`, `i`, `[`, `]`, `\`, `T`, `f`, `g`/`G`, `ctrl+up`, …) need no entry. Update `USAGE.md`'s Keyboard Reference either way. **Enforced** one way by `TestKeymapParity` (`app/keymap_parity_test.go`): every key in `keys.GlobalkeyBindings` is bound in the defaults; **Convention** for the docs — help that advertises a key that no longer does what it says.
- **Changing the Lua API or an error it raises?** Update `docs/specs/scripting.md` in the same change: user scripts are written against it, and a refusal raises its own message (`"kill x: not allowed on a workspace terminal"`) or `"<op>: <err>"`. **Convention** — scripts written against an API that no longer exists.
