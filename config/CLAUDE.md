# config

Loom's on-disk configuration (`config.json`), app state (`state.json`), profiles and workspace registry (`workspaces.json`), and the resolution of the dirs that hold them. Full reference in [`README.md`](README.md).

## Rules when modifying this package

- **Adding a setting?** Put the field in `Settings` (`config/settings.go`), read it through a getter that maps nil or empty to the default, and deep-copy it in `Clone` when it is a pointer, slice or map. `Config` embeds `Settings` beside its mutex and JSON flattens the embedded struct, so `config.json`'s format stays unchanged; `FromSettings`, `Snapshot` and `ReplaceSettings` all copy through `Clone`, so a field it misses is shared between the settings overlay's copy and the model's. **Enforced** for today's fields by `TestSettings_CloneSharesNothing` and `TestSettings_ConfigJSONIsUnchanged` (`config/settings_test.go`); **Convention** for a new one — an overlay edit that changes the model's settings before it is saved. Guide: [`../docs/claude/launch-options.md`](../docs/claude/launch-options.md)
- **Touch a shared `Config` only under its lock.** Copy settings out and in with `Snapshot`/`ReplaceSettings`, write through `Mutate`, read through the locked getters (`GetBranchPrefix`, …), and let `SaveConfigTo` marshal under the read lock; never call a locked getter or `Mutate` inside a `Mutate` callback, since the lock is not reentrant. **Enforced** under `-race` by `TestConfigMutateIsRaceSafeWithGetBranchPrefix` and by `TestConfig_SnapshotAndReplaceAreCopies`; a reentrant call deadlocks.
- **Write `WorkspaceRegistry` only through the model.** Unlike `config.State` it has no mutex, so its writes (`Add`, `UpdateLastUsed`, `SetOpenWorkspaces`) run on the model's goroutine, behind `core.Model.Register`, `SetLastUsed` and `PersistOpenList`; each write rereads the file first so another process's change survives. **Enforced** for the TUI by `TestTUIHoldsNoModelObject` (`internal/testenv/instance_enforce_test.go`), which bans `config.WorkspaceRegistry` from `app/`, `ui/` and `script/`; **Convention** elsewhere — a lost registry write.
- **Keep the empty-dir and global-dir semantics.** `LoadConfigFrom("")` and `LoadStateFrom("")` mean "use the default directory"; `GetGlobalConfigDir` follows `LOOM_GLOBAL_DIR` and ignores `LOOM_HOME` by design, since the registry and the global workspace are one per daemon while `LOOM_HOME` is a backward-compatible fallback for a process's own config dir. **Enforced** by `TestGetGlobalConfigDir` (`config/workspace_test.go`) and `TestGetGlobalConfigDir_EnvOverride`.
- **Write config, state and registry files atomically and quarantine a corrupt one** (`AtomicWriteFile`, `quarantineCorruptFile`). A torn write or an overwritten corrupt file loses the user's settings or sessions for good; a quarantined one can be recovered by hand. **Enforced** by `TestAtomicWriteFile_…`, `TestLoadConfigFrom_CorruptFileQuarantined` and `TestLoadStateFrom_CorruptFileQuarantined`.
- **Keep `MigrateLegacyHome` idempotent and hands-off when a dir is set explicitly.** It runs on every startup, renaming `~/.claude-squad` to `~/.loom` once, and skips when `LOOM_HOME`, `CLAUDE_SQUAD_HOME` or `LOOM_GLOBAL_DIR` is set. **Enforced** by `TestMigrateLegacyHome_…` (`config/migration_test.go`).
- **Isolate `HOME`, not the loom dirs, in this package's tests.** They exercise default resolution, so `TestMain` (`config/config_test.go`) leaves `LOOM_HOME`, `CLAUDE_SQUAD_HOME` and `LOOM_GLOBAL_DIR` unset and points `HOME` at a throwaway; assert "default is `~/.loom`" by computing `os.UserHomeDir()`, never by touching it. **Enforced** by `TestDefaultDirsResolveUnderThrowawayHome`.
