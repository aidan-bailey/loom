# account

Extra Claude accounts: each is a `CLAUDE_CONFIG_DIR` under `<globalDir>/accounts/<name>/`, linked to the main config dir and registered in `accounts.json`; this package creates, syncs, logs in, probes and removes them, through an injected executor. Full reference in [`README.md`](README.md).

## Rules when modifying this package

- **Act on an account's dir only through `OwnedDir`'s canonical path, never the registry's stored `Dir`.** A stored `<AccountsDir>/lnk/../name` cleans lexically to the canonical path while a symlinked `lnk` makes the kernel resolve it elsewhere first, so acting on the raw string once deleted real content outside the account's dir. A dir the account doesn't own is unregistered and left on disk. **Enforced** by `TestRemove_NeverDeletesOutsideItsOwnAccountDir`, `TestRemove_OutsideAccountsDirOnlyUnregisters` and `TestOwnedDir_…` (`account/link_test.go`).
- **Validate every entry `LoadRegistry` loads, latch on any failure, then canonicalize.** An invalid or duplicate name, a non-absolute dir, or one that doesn't resolve to `<AccountsDir>/<name>` (`resolvedOrClean`: `EvalSymlinks` on the raw path first, so a `lnk/..` can't cancel lexically) zeroes the list and refuses every write (`ErrRegistryLoadFailed`), as a file that won't parse does; `canonicalizeDirs` then sets each `Dir` to `filepath.Join(AccountsDir, name)`, because the stored `Dir` is what every launch passes as `CLAUDE_CONFIG_DIR`. **Enforced** by `TestLoadRegistry_RejectsInvalidStoredEntries`, `TestLoadRegistry_RejectsALnkDotDotDisguisedDir`, `TestRegistry_CorruptFileLatchesWrites` and, for the canonical spelling, `TestLoadRegistry_ToleratesADifferentlySpelledGlobalDirAcrossRuns` (`account/registry_test.go`).
- **Never let `Sync` replace a real file, or `Remove` delete one without force.** A link turned into a file (an atomic rewrite through it) is reported as diverged, since it may hold the only copy of a change; without `force`, `Remove` refuses (`*UnsharedError`) while `Unshared` finds real entries not shared with the main dir, and an owned dir's `os.RemoveAll` deletes the links without following them. **Enforced** by `TestSync_ReportsADivergedRealFileAndKeepsIt`, `TestRemove_RefusesWhenAccountHoldsUnsharedFiles` and `TestRemove_DeletesLinksButNeverTheirTargets`.
- **Keep every per-account entry on the deny-list (`sharedDenyList` and `shared`, `account/link.go`).** Everything else in the main config dir is linked, so a credential, account-state or runtime file Claude starts writing is shared across accounts until it joins the list. **Enforced** for the credentials and `.claude.json` variants, `daemon.log`, `stats-cache.json`, `.last-cleanup`, `jobs` and the per-session security-warning files by `TestSync_Excludes…` (`account/link_test.go`); **Convention** for `session-env`, `ide`, `debug`, `cache`, `backups`, `shell-snapshots`, `statsig` and any new entry — one account's credentials or runtime state showing under another.
- **Validate the main dir before linking from it (`ValidateMainDir`).** It must be absolute, symlink-resolved, and neither inside nor containing the accounts dir; `add`, `sync`, `Create` and core's background re-sync all check it, or an account ends up linked to itself or to another account. **Enforced** by `TestValidateMainDir_MatchesWhatCreateRejects`, `TestCreate_Rejects…` and, for the re-sync, `TestAccountsRefresh_SkipsSyncForAnUnsafeMainDir` (`core/accounts_test.go`).
- **Seed the main dir's `projects/` in `Create` before linking, when the main dir exists.** Claude creates it lazily on a config dir's first session, so the first account made on a fresh install would never link it, and cross-account `--resume` would have nothing to share. **Enforced** by `TestCreate_BootstrapsMainProjectsDirSoAccountsShareResumeHistory`.
- **Run every account-scoped `claude` subprocess that captures output through `Command`.** It refuses a missing `CLAUDE_CONFIG_DIR` (`ErrAccountDirMissing`) rather than let the CLI recreate it empty and logged out. `LoginCmd` returns a bare interactive command that `Command` can't gate, so each caller (`cmd/account.go`, and `accountLoginCmd` in `app/accounts.go`) stats the dir first. **Enforced** by `TestCommand_RefusesAMissingAccountDir` (`account/command_test.go`), `TestAuthStatus_RefusesAMissingAccountDir` and `TestProbeUsage_RefusesAMissingAccountDir`.
- **Mark onboarding only for a logged-in account, and never rewrite a file that won't parse** (`EnsureOnboarded`). `claude auth login` leaves `.claude.json`'s `hasCompletedOnboarding` unset, so the first session would ask to log in again; every other key is kept, and a failure is logged, not fatal. **Enforced** by `TestEnsureOnboarded_…` (`account/onboard_test.go`).
- **Read credential overrides from the running process's environment, and keep `CredentialOverrides` in step with the Claude CLI.** `ActiveCredentialOverride` returns the first set of the env vars the CLI checks before a config dir's own credentials; in the daemon that is its spawn-time environment, which every client warns by. **Enforced** for the read by `TestActiveCredentialOverride_…` (`account/override_test.go`); **Convention** for the list — accounts silently billing a credential nobody warns about.
- **Import nothing from `app`, `ui` or `session`.** `app` and `session` import this package, and `ui` reaches it through `core`, so it stays a leaf, with its executor injected. **Enforced** by the compiler: each of those imports is a cycle.
