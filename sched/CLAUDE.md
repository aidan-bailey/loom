# sched

The work scheduler's package: the job, claim, caps and policy types, `Resolve` (the host's defaults and the bounds of the `scheduler` config block), `Admit` (first fit with a starvation guard, saying why each job waits), `Hints` (the parallelism variables), the submission checks, and the `jobs.json` store with the per-job files; and the runtime that hosts a running job (the detached `loom job-shim` process, the lock probe, group signals, the usage sampler and host detection). The model in `core` owns the queue and calls this package from its loop; the logic half runs no process, and nothing in the package keeps state of its own.

## Rules when modifying this package

- **Keep every bound of a submission in `Submit.Validate` and `CheckClaim`, with the texts written there.** The model runs them for every client, so the CLI, the work view and a script meet the same bounds; a client that checks its own lets them drift, and a reworded text silently stops matching the tests and the CLI output that quote it. **Enforced** for the bounds and texts by `TestSubmit_Validate`, `TestSubmit_ValidateReportsTheFirstFault` and `TestCheckClaim` (`sched/job_test.go`); **Convention** for other packages' matches — a test elsewhere that matches a stale text.
- **Make `Resolve` fail closed: a field outside its bounds, a default claim above a cap, and an unreadable RAM with `memory_gb` unset are errors, never a clamp or a guessed cap.** The model pauses admission on the error and the view says why; a clamped or guessed cap admits work the owner did not allow, or over-commits the host, and nothing says so. **Enforced** by `TestResolve_Bounds` and `TestResolve_RAMUnreadable` (`sched/policy_test.go`), and for the defaults by `TestResolve_Defaults`.
- **Keep `Admit` a pure function of its arguments, and never let it start a job that does not fit what the running jobs leave.** The model calls it on its loop with the records, the policy and the time, so a clock, file or process inside it blocks every client, and a pass that overshoots a cap is the memory exhaustion the queue exists to prevent. **Enforced** for the fit by `TestAdmit_FirstFit`, `TestAdmit_ExclusiveClaims` and `TestAdmit_CapEditsAndQueueOrder` (`sched/admit_test.go`); **Convention** for the purity — a pass that blocks the loop, or a table that passes on one machine only.
- **Keep the starvation guard and the over-cap skip: an over-cap job is never the head, and a head that has waited `StarveAfter` starts alone or holds the rest back.** Without the guard smaller jobs pass a large one forever; with an over-cap head the whole queue stalls behind a job that can never run, and the view shows a wait nobody can end. **Enforced** by `TestAdmit_StarvationGuard` and `TestAdmit_OverCapJobsAreSkipped`.
- **Make `Hints` add only what the submitter's environment lacks, and always set `LOOM_JOB`.** A job that set its own parallelism keeps it, and a `LOOM_JOB` inherited from an outer job would name the wrong job to `loom job`. **Enforced** by `TestHints_KeepsWhatTheSubmitterSet` and `TestHints_ReplacesAnInheritedLoomJob` (`sched/hints_test.go`).
- **Make `RemoveJobDir` the only removal in this package, and build its path from the ID; its callers are retention and `submitJob`'s take-back of a directory it just created.** It removes `JobDir(dir, id)` with `os.RemoveAll`, so a path read from a file (a record, `spec.json`) must never reach it: such a path could name any tree, and a deleted tree is gone. It refuses an empty, relative or unclean `dir` (`JobDir("", 7)` is `7` in whatever directory the daemon runs in, and a `..` after a link cleans lexically to another tree than the kernel reaches) and an ID below 1, and it never follows a link. **Enforced** by `TestRemoveJobDir_RemovesOnlyThatJobsDir`, `TestRemoveJobDir_DoesNotFollowLinks`, `TestRemoveJobDir_RefusesWhatItCannotProve` and, for the only-removal, `TestSched_RemoveAllIsOnlyInRemoveJobDir` (`sched/files_test.go`), whose matcher `TestRemoveAllCallers_Detection` pins.
- **Read `jobs.json` only through `LoadStore`, and leave a file that fails to load untouched.** `LoadStore` never writes: an unreadable, invalid or newer-version file (`ErrNewerStore`, found before the rest is parsed) pauses admission and refuses submissions while the running shims carry on, and an overwrite with an empty store would drop every queued job and the running ones' records for good. **Enforced** by `TestLoadStore_NewerVersionIsLeftUntouched` and `TestLoadStore_InvalidFilesAreLeftUntouched` (`sched/store_test.go`).
- **Write `jobs.json` and the per-job files only through `config.AtomicWriteFile` (0600, in 0700 directories), and let `NextID` only go up.** A torn file loses the queue or a result; the job directory is named by the ID, so a reused ID hands a new job an old job's `output.log`, `exit.json` and lock. `SaveStore` stamps `StoreVersion`, and `LoadStore` raises `NextID` past the highest ID in the file and the highest numeric job directory. **Enforced** for the modes, the format and the counter by `TestSaveStore_ModesAndFormat`, `TestShimFiles_RoundTrip`, `TestLoadStore_RaisesNextIDPastEveryJob` and `TestLoadStore_RaisesNextIDPastEveryJobDirectory`; **Convention** for the routing through `AtomicWriteFile` — a torn file after a crash mid-write.
- **Signal a job's process group only through `SignalGroup`, and only once the caller has proved the group is the job's.** `SignalGroup` refuses a pgid of 1 or below and this process's own group, since `kill(0)` signals the caller's group and `kill(-1)` every process; it cannot tell a group that is still the job's from one a reused pid now leads, so the proof is the caller's: the shim's `run.lock` held (`Probe`), or, for a lost job, a sample showing members in the group and no process with the shim's pid (`Snapshot.Group`). A signal to a group that is not the job's kills unrelated work, silently. **Enforced** for the refusals by `TestSignalGroup_RefusesAGroupItCouldNotMean`; **Convention** for the proof, which is the caller's — a SIGKILL to someone else's group.
- **Build the job's environment from its `spec.json` and the hints alone, and the shim process's from `os.Environ()` plus `Runner.Env`.** The shim runs in the daemon's environment (its tmux server, `CLAUDE_CONFIG_DIR`, `LOOM_*` variables); passing that on would make every build behave unlike the one the submitter's shell would have run. **Enforced** by `TestRunShim_TheJobSeesOnlyTheSubmittersEnvironment`.
- **Find the command on the `PATH` of the job's environment, never the shim's.** The shim's `PATH` is the daemon's, and the submitter's shell chose the `cargo` or `python` it meant, so a lookup in the daemon's finds another build or none. **Enforced** by `TestResolveCommand` and `TestRunShim_FindsTheCommandOnTheSubmittersPath`.
- **Catch the shim's signals with `signal.Notify`, never ignore them, and leave delivery to the command to the group send.** An ignored signal stays ignored across `exec`, so the command would shrug off its cancel and run until the daemon's SIGKILL; a forwarded copy on top of the group's would signal the command twice. **Enforced** by `TestRunShim_ACancelReachesTheCommandAndItsChildrenThroughTheGroup`.
- **Write `exit.json` before the shim lets go of `run.lock`, and keep the lock close-on-exec (Go's default for `os.OpenFile`).** A free lock is the daemon's cue that the shim is gone and `exit.json` is final; a lock released first settles a finished job `lost` and has its group killed, and a lock a leftover child inherited stays held after the shim exits, so the job never settles. **Enforced** for the child by `TestRunShim_ALeftoverChildDoesNotKeepTheLock` and for the held and released states by `TestRunShim_HoldsTheLockWhileTheCommandRuns`; **Convention** for the write coming first — a `lost` job that finished.
- **Run the shim as the leader of its own process group, and refuse to run as anything else.** The daemon signals `-pid` as the job's group and starts the shim with `Setsid`; a shim that led no group would leave every signal and sample to a group that is not the job's. **Enforced** by `TestRunShim_RefusesToRunWhenItLeadsNoGroup`.
- **Lower the nice value and I/O class on the thread that forks the command (`runtime.LockOSThread` at the top of `RunShim`).** Linux keeps both per thread and a child inherits its forking thread's, so a setting made on another thread leaves the command at the default priority, silently. **Enforced** for the settings by `TestRunShim_LowersTheCommandsPriority` and `TestRunShim_SetsTheCommandsIOClass`; **Convention** for the pinning — a command that runs at full priority now and then.
- **Keep syscalls and process control in `shim_unix.go`, `prio_linux.go`, `prio_other.go` and `host_*.go`, leave `shim_windows.go` as stubs that answer `ErrUnsupported`, and run `GOOS=windows CGO_ENABLED=0 go build ./...` and the same for `darwin` after touching them.** CI builds no Windows binary, but the release does. **Convention** — a release that fails to build.
- **Call `MaybeRunTestShim()` first in the `TestMain` of every package whose tests start real shims, and run their jobs through `TestRunner()`.** A test binary has no `job-shim` command; started as the shim without the hook it runs the whole suite again, and each run starts more shims. **Convention** — a runaway test run.

- **Keep `Size`, `Usual`, `OverdueAfter`, `RunOf`, `ScalingOf` and `Grant` pure functions of their arguments, and let a floor only raise a memory claim.** The model calls them on its loop at every submit and admission pass; a floor that set a claim alone would teach a failing build's small peak to the next good run, which then runs over its claim, and nothing says so. **Enforced** by `TestSize` (its "a failed run's peak only raises", "a prior raised by a floor" and "runs with spare cores" cases) and `TestRunOf` (`sched/belief_test.go`); **Convention** for the purity — a pass that blocks every client.
- **Check a job's named locks (`Record.Locks`) before its fit, and leave a job blocked on a running job's lock out of the line, like an over-cap one.** Two jobs naming one lock exist to never run together (a fixed port), and a blocked job made the starving head would hold the whole queue behind a holder that may run for an hour, with only its wait to say why. **Enforced** by `TestAdmit_Locks` (`sched/admit_test.go`).
- **Measure the starvation guard's wait from `Record.QueuedSince` (`Ready`, else `Submitted`), and never admit a held job.** A released dependent's chain may have begun long before the dependent joined the queue: counted from its submit it is a starving head at once, which starts alone or holds every other job back, and nothing says why. **Enforced** by `TestAdmit_StarvationCountsFromReady` (`sched/admit_test.go`).
- **Hash a signature's `After` only when it is set, and write `beliefs.json` as version 2 only while a belief has one (`Beliefs.fileVersion`).** An ID that changed for a signature with no prerequisite orphans every command's history; an older loom computes a dependent's ID without its part and refuses the whole file, while a version it doesn't read is left untouched with a reason. **Enforced** by `TestSignature_IDWithAPrerequisite` (its pinned ID) and `TestBeliefsStore_VersionFollowsThePrerequisiteParts`.
- **Keep `FamilyOf` a pure function of the signature's repo, folder and command, and give a job no family on any doubt (`splitScript`'s `errScript`, no step but `cd`).** A family lends its runs' claims to a job that has none; a guess that merges two commands lends one's memory to the other, and nothing says so until the host swaps. **Enforced** by `TestFamilyOf` (its no-family rows) and `TestSplitScript` (its failures).
- **Keep the family out of `SignatureID` and out of `recordRun`: a run is recorded only in its own belief, and a family is only a fallback after a job's own runs.** A family in the ID would orphan every belief, and a run recorded in its relatives would teach them a command they don't run. **Enforced** by `TestSignature_IDWithAPrerequisite` (its pinned ID) and `TestSize_FromTheFamily` ("the job's own runs win").
- **Read only a job's own runs in `OverdueAfter`, `Predict`/`CurvedRuns`, `Hold`, `ScalingOf` and `SpareWidth`/`Grant`; only `Size`, `NeedsPrior` and `Usual` take a family pool.** A family mixes filtered and full runs: its curves would release memory a job still needs, its durations flag a full suite overdue, and its cores earn no grant. **Enforced** for overdue by `TestUsual_FromTheFamily` and for grants by `TestGrant` (its family case); **Convention** for curves and holds — memory handed out early, and nothing says so.
- **Let `Grant` lend nothing while a queued job waits for anything but the caps, never lend into the reserve (the default claim), and let `Size` count an overrunner's cores past the default claim only up to the cap.** A grant made while a job waits keeps that job waiting for the whole run, and one into the reserve leaves the next default job no room; nothing would say so. **Enforced** by `TestGrant` (its waiting, reserve and starved-head cases) and `TestSize` (its overrunner cases).
- **Find a job's repository only from git's files (`FindRepo`), never with a git subprocess.** `submitJob` runs it on the loop: a subprocess there would block every client for as long as git takes. **Enforced** for the layouts (a checkout, a worktree, a relative `gitdir:`, none, a broken `.git`) by `TestFindRepo`; **Convention** for the no-subprocess part.
- **Read `beliefs.json` only through `LoadBeliefs`, write it only through `SaveBeliefs`, and leave a file that fails to load untouched.** An overwrite with an empty registry would drop every command's history for good. **Enforced** by `TestBeliefsStore_RoundTripAndRefusals` (`sched/belief_test.go`).
- **Sum a job's usage over its session (`Snapshot.Session`), but prove a lost job's group by its group (`Snapshot.Group`).** The shim leads both; a child that changes group (coreutils `timeout`) stays in the session, so usage by group misses it and its memory, while the group signal reaches only the group, so a proof by session would kill on evidence about processes the signal never reaches. **Enforced** by `TestSnapshot_Session` and `TestJobQueue_UsageSumsTheJobsSession`; the proof's tests (`orphanedGroup`) stand unchanged.
- **Keep `Hold`, `BuildProfile` and `BuildCurve` pure, never let a released hold rise, and never let a compressed staircase or curve fall below the run it came from.** The model calls them on its loop at every sample, pass and settle; a staircase or curve below its run, or a hold that fell to a level history doesn't show, hands out memory a job will use again, and nothing says so until the host swaps. **Enforced** by `TestBuildProfile_NeverBelowTheRun`, `TestBuildCurve_NeverBelowTheRunAndCompressed`, `TestHold_AfterRelease`, `TestHold_EachRuleHoldsTheClaim` and `TestHold_PerResourceRules`.
- **Measure a job's CPU time from its rusage, and its I/O from the shim's `/proc/self/io` read before the command starts and after it is reaped.** The kernel adds a reaped child's counters, and its reaped descendants', to its parent's only at the reap, so a reading taken earlier misses the job. **Enforced** by `TestRunShim_RecordsTheCommandsCPUTimeAndIO` and `TestIOCounters`.
- **Keep agent jobs (`KindAgent`) out of the caps, the advisor, grants and parallelism hints, and admit them only by `Policy.AgentJobs` per account key (`Record.AccountKey`, the job's `CLAUDE_CONFIG_DIR`).** An agent holding a claim while it waits on builds it queued itself starves them when several runs go at once, and a hinted 1 would run its own `cargo check` single-threaded; a queued agent made the head would hold every build back behind a job the caps never govern. **Enforced** by `TestAdmit_AgentJobs`, `TestGrant_PassesAgentJobsOver`, `TestAgentHints_OnlyTheJobAndSccache` and `TestSubmit_Validate` (its agent cases).

- **Keep `AdmitGreedy`, `Predict` and `PeakSum` pure, and never let `AdmitGreedy` start a job whose prediction, summed with the running jobs' and the pass's earlier starts', passes the budget.** The model calls them at every sample while jobs wait; a start past the budget is the memory exhaustion the ladder then has to undo. **Enforced** by `TestAdmitGreedy_PeaksThatMeetWait` and `TestAdmitGreedy_JobsStartedInThePassCount`.
- **Keep `Ladder` pure, never let a squeeze set a `MemoryHigh` of 0 (`minHighKB`), and never ladder an exclusive job, one requeued `MaxRequeues` times, or a paused `--no-requeue` one further.** 0 is no limit to systemd, and a requeue of a job that asked for none loses its work. **Enforced** by `TestLadder_SqueezeHasAFloor`, `TestLadder_VictimOrder` and `TestLadder_SqueezeThenPauseThenRequeue`.
- **Join the scope before the command starts (`joinScope` before `startCommand`), and run the command uncontained, with the reason in `started.json`, when the join fails.** A process moved after it forked leaves its children behind, and a job refused for want of a scope is work lost. **Enforced** for the fallback by `TestRunShim_RunsUncontainedWhenItCannotJoinItsScope`; **Convention** for the order — a job half in its scope.
- **Keep `Borrow`, `BorrowFits` and `GiveBack` pure, count every borrower at its prediction (borrowers lend to no one), and let `CgroupReclaim` refuse anything but a job's scope.** The model calls them at every pass and sample; a borrower counted at its use lends a second borrower memory both can claim back at once, which nothing but the emergency ladder then gives back, and a reclaim of a parent cgroup pushes the user's session to swap. **Enforced** by `TestBorrow_BorrowersLendToNoOne`, `TestGiveBack_TheStakeDecidesRequeueOrLend` and `TestCgroupReclaim`.
- **Let `NewConfiner`'s context bound the dial only, never the connection (`dialConfiner`).** godbus closes a connection once the context it was dialed with ends, and the daemon's probes cancel theirs on return, so a confiner tied to it fails every later call ("connection closed by user") and every job runs uncontained, with only a log line saying so. **Enforced** by `TestDialConfiner_TheConnectionOutlivesTheDialContext` and, on the real bus, `TestConfiner_Live_OutlivesItsDialContext` (`-tags systemd_live`).
- **Write `cgroup.kill` only through `CgroupKill`, which refuses anything but a loom job's scope, and name the slice with no dash (`SliceName`).** A kill of a parent cgroup reaches every process below it, the user's session included; a dash in a slice's name nests it in `loom.slice`, whose weight is then all the agents' panes compete with. **Enforced** by `TestCgroupKill_RefusesWhatIsNotAJobScope` and `TestUnitNames`, and for the slice's place by `TestConfiner_Live` (`-tags systemd_live`).
