# ui

Bubble Tea view components (rail, cards, overview, split pane, panes, workbench, overlays and the embedded review pane) that render `core.InstanceView` copies, plus the registry of the TUI's agent-pane attach clients. Full reference in [`README.md`](README.md).

## Rules when modifying this package

- **Build every theme-derived style inside a `RegisterThemeHook` callback, from color roles only** (`ui/theme.go`). A package-level `lipgloss.Style` built in a var initializer captures the colors from before `ApplyTheme` and stays stale when the settings overlay switches themes live; a literal color ignores the theme altogether. Glamour styles rebuild in a hook too (`ui/markdown_style.go`), and `MarkdownPane` re-renders lazily off `mdStyleGen`. **Convention** — a live theme switch leaves the widget in the old colors; `TestApplyTheme_RebuildsHookedStyles` (`ui/theme_test.go`) and `TestMarkdownStyle_RebuildsOnApplyTheme` pin only the existing hooks.
- **Render only view copies, never an instance.** The rail, cards, overview, menu, split pane, panes and workbench hold `core.InstanceView` values, so nothing here mutates the model or calls a display method on what an instance holds. **Enforced** by `TestTUIHoldsNoModelObject` (`internal/testenv/instance_enforce_test.go`), which covers `ui/`.
- **Keep the rail's selection by `InstanceID`, re-resolved on every read.** `List` only reads its `InstanceSource` (adds, removals and replacements are edits of the slot's store), and `SelectID`/`resolveSelection` keep the selection on its row when rows above it come or go; a removed row's selection moves to the row that slid into its place, or the new last row (`lostSelectionRow`). A cached index silently retargets the selection to a neighbour. **Enforced** by `TestList_…` (`ui/list_remove_test.go`).
- **Call `ScrollModel.AdvanceAndRender` exactly once per render pass.** It advances the anchor state as well as rendering, for both `PreviewPane` and `TerminalPane` on the emulator path; a second call while output arrives drifts the "new lines below" count. **Convention** — a wrong new-lines counter, never a corrupted window.
- **Keep `TerminalPane.updateContentSnapshotLocked`'s Unlock, capture, Lock trio strictly paired.** It releases `t.mu` around `CaptureHistory` while its caller holds the lock through a deferred Unlock, so a return or a panicking call between them double-unlocks: "fatal error: sync: unlock of unlocked mutex". **Convention** — a crash on the snapshot path only, which most runs never take.
- **Release terminal-pane clients with `DetachAll`/`DetachExcept`, never `Close`.** `Close` kills the `loom_term_` shell the user may still be using; a detach leaves it running. **Enforced** by `TestTerminalPane_DetachAllHandsOverWithoutKilling` (`ui/terminal_test.go`).
- **Start a terminal-pane shell only for an active row.** `ensureSessionLocked` is gated on `InstanceView.Active()`: a kill or pause ends the row's shell in its job while the row still reads Deleting or Loading, and a shell started in that window outlives the row, since the prune after it only detaches (a fast `D`, `y` once hit that window every time). **Enforced** by `TestTerminalPane_NoNewShellForInactiveRow` (`ui/terminal_test.go`).
- **Judge a pane client by `TmuxSession.Attached`, never `PtmxAlive`.** `PaneClients.Ensure`, `Alive` and `ui.Pane.Attached` go by it, because `PtmxAlive` stays true after the pump's EOF: a client left on a session that died and was relaunched under its name would show "[exited]" forever. `Ensure` leaves a client whose pump exits within `quickExitHoldoff` of attaching to the health tick, so an attach that dies at once (tmux under a TERM it can't use) can't loop. **Enforced** for `Ensure` by `TestPaneClients_EnsureReattachesAnExitedClient` and `TestPaneClients_EnsureHoldsOffAClientThatExitsOnAttach` (`ui/panes_test.go`); **Convention** for `Alive` and `ui.Pane.Attached` — a dead client treated as live, or a live one repaired forever.
- **Hand a client out for closing only from `Retain` or `Replace`.** A client is closed only after the registry has dropped it, so nothing re-attaches or double-closes it while it closes (`Ensure` builds a new one); the pump bookkeeping a close runs (`waitPumpExit`) is unlocked. **Enforced** by `TestPaneClients_ReplaceHandsBackTheOldClient`, `TestPaneClients_RetainDropsTheUnwanted` and `TestPaneClients_EnsureAfterRetainBuildsANewClient`.
- **Keep only the `ReviewPane` interface in package `ui`.** `ui/review` (package `reviewui`) imports `ui` for its theme hooks, so `ui` naming `reviewui.Pane` would cycle; the workbench holds the interface. **Enforced** by the compiler: an import cycle fails the build.
- **In `ui/review`, keep per-file work inside the `LoadCmd` closure, over locals snapshotted when it is built.** `NewDocPane` and `NewCodePane` run on the Update goroutine, so a `gitdiff.DiffFile` or document read there stalls the UI for every file in the review. **Convention** — a UI stall per reviewed file; `TestNewCodePane_DefersDiffToLoad` can't catch it, since its root is no repository and a diff taken in the constructor would leave the same empty fields.
- **In `ui/review`, claim idle keys narrowly (`claimsIdleKey`) and capture everything only while `Busy()`.** An idle pane that claims more swallows the workbench's panel tabs, session ops, attach, workspace navigation and `esc`. **Enforced** for its sampled keys by `TestPane_IdleKeyClaimsAreNarrow` and `TestPane_BusyCapturesEverything`, and for `esc` by `TestPane_EscFallsThroughWhenIdle` (`ui/review/pane_test.go`); **Convention** for the attach keys — `i` or `ctrl+a` typed into the review instead of attaching.
- **Size bordered boxes as lipgloss v2 does: `.Width`/`.Height` are the whole box, border included, and `.Height` is only a minimum.** Subtracting `GetHorizontalFrameSize()` makes the box too narrow, so its border falls short of its siblings' edge, and over-tall content grows the box instead of clipping. **Enforced** for the width half on the split pane by `TestPaneBorderReachesRightEdge` and `TestSplitPaneStringBordersReachRightEdge` (`ui/pane_border_test.go`); **Convention** for the height half — a box that grows past its row. Guide: [`../docs/claude/ui-geometry.md`](../docs/claude/ui-geometry.md)
- **Count the account strip's row in the top chrome: lay out and hit-test the panes below `topChromeHeight` (`app/app.go`), never `tabBar.Height()` alone.** The strip (`AccountStrip`) renders a row above the tab bar whenever an extra account exists, so sizing from the tab bar alone pushes the panes off the bottom and offsets every mouse selection by that row. **Enforced** by `TestTopChromeHeight_CountsTheStrip` and `TestView_StripIsTheTopRowLeftAligned` (`app/top_chrome_test.go`).
